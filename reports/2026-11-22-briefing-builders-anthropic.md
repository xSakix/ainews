## Local models and agents

- Oscar runs mixture-of-experts models far larger than a Mac's memory — A Rust service for Apple Silicon that treats unified memory as elastic (it takes spare memory and hands it back when other apps need it), keeps layers whose experts fit entirely on the GPU, and pages the rest from disk with router-lookahead prefetching, optional self-drafting and custom Metal kernels. On a MacBook Pro M5 Max with 64 GB (Oscar capped at 52 GB) the author reports 151 tok/s decode on Qwen3.6-35B-A3B (20 GB), 25.1 tok/s on a 178B model (113 GB), 12.4 tok/s on Qwen3.5-397B-A17B (161 GB), and 1.6-1.7 tok/s on Kimi K3/K3.1 Pro (577-629 GB, roughly 9-10 times the machine's memory). The catch: the largest models are batch-speed only, one machine and one setting were measured, an optional approximate-routing mode can change outputs, and the build is not notarised. The repo is a single commit created on 20 November. Built by: "prp" (copyright held by Imperial College London) · Artefacts: code (MIT or Apache-2.0) · Signal: 18 GitHub stars. Source: https://github.com/prp/oscar

- LookAtMyQuant publishes new Inkling-2-Mini builds, and Hacker News disputes the "12x" headline — A quantization compiler (MIT, trellis codes, per-row bit allocation by Fisher information, 4,000 distillation steps, MLX runtime for Apple Silicon plus a speculative-decoding drafter). This week's development is four builds of Thinking Machines' Inkling-2-Mini from 5.38 to 12.76 GB (from 18.89 GB of text weights); the author reports the 5.4 GB build at 88.0% GSM8K and 70.7% HumanEval, and drafted decode of about 104-125 tok/s on an M5 Max. The headline claim is 12 times lower KL than Q4_K_M at the same size, measured on Gemma 4 E2B. In the HN thread (376 points) a commenter compared the KL numbers with Unsloth's UD-IQ1_S and reported worse results on English/chat/code (0.0895 vs 0.0808) and across 13 languages (0.287 vs 0.124), and others questioned undisclosed calibration data; the author did not reply. Files are Apple-Silicon/MX only for now, the llama.cpp GGUF path is not working yet, and dense weights and the 16-bit drafter are unpublished. Reported speeds on other hardware: about 6.7 tok/s on an 8 GB RTX 4060 laptop, 30-45 tok/s on Strix Halo. The repo itself dates from 31 October; the new Inkling builds are the in-window release. Built by: ShinMegamiBoson (individual) · Artefacts: code (MIT), weights on Hugging Face · Signal: 310 stars, 376 HN points. Source: https://github.com/ShinMegamiBoson/lookatmyquant (discussion: https://news.ycombinator.com/item?id=50591853)

- A 97-hypothesis playbook for running huge MoE models on four RTX 3090s — A living notebook, also packaged as an agent skill (SKILL.md plus two stdlib Python tools), documenting what did and did not speed up 100B-class MoE models with experts held in system RAM. Reported gains: DeepSeek V4.1 Flash prefill at 32K from 430 to 2,199 tok/s on four cards; Inkling 2 Mini on one card from 57 tok/s (llama.cpp) to 128.7 tok/s at 344K context; GLM-5.3-Flash at 2.05 bpw from 48.3 to 66-68 tok/s decode by switching to tensor parallel; a drafter lifted Qwen3.8-Flash-Next decode 44-46%. It also records negative results: training a drafter on the author's own data gave little on three models, and a short benchmark predicting +27% decode gave +2% in real generation. All numbers come from one rig with no harness included; the description says 97 hypotheses while the README says 115. Built by: Alesha (alesha-pro) · Artefacts: write-up and code (MIT) · Signal: 56 stars. Source: https://github.com/alesha-pro/inference-optimization-playbook

- Pi Bot, a local-first desktop team of named agents — An Electron app (React Native on Android, relay on a Cloudflare Worker) where you chat with one bot or a group chat whose coordinator drafts a plan you confirm; bots run commands, edit files, browse and use the computer inside a sandbox built on Anthropic's sandbox-runtime, with every tool call going through one policy engine and an audit log. ## Open-source projects and tools

- fast-anything: "rewrite the 5% that's slow" in Rust with an agent, checked against recorded calls — A Claude Code plugin/MCP server/skill that profiles a Python, Node, Ruby, Java, Go, PHP, C or C++ app, ranks hot functions, has Claude or Codex port one function to Rust, replays up to 500 recorded real calls to verify output (floats within 1e-9), and swaps the port in only if it matches and is faster; one command reverts. Author's benchmarks (i5-10500, Windows 11): Python fuzzy-dedupe 4.91 s to 42 ms (116x), PHP 55x, TypeScript 20x, Go 21x, Ruby 14x, Java 3x, C++ 2.7x. These are the author's own workloads; only top-level deterministic functions taking plain data can be ported, and a Rust toolchain is needed. Created 21 November. Built by: EL4CTEO (individual) · Artefacts: code (MIT) · Signal: 153 stars. Source: https://github.com/EL4CTEO/fast-anything

## Experiments, demos and write-ups

- Can an LLM read and write executables byte by byte? — George Xenos and Sotiris Giannopoulos gave a model an `xxd` hex dump with no tools (single attempt, no feedback). It identified four programs including a 67 KB stripped, partly obfuscated FreeBSD `ministat` (and reportedly found a real bug in its confidence table), patched three programs by editing 1.4-5.9% of bytes with all passing hidden tests under qemu, wrote three ELF64 programs (391 B, 4,144 B, 3,584 B) matching a GCC reference, and correctly summarised a 4,608-byte PE malware sample (all 13 recovered API-name hashes confirmed against a VMRay report). An open-weight model (DeepSeek V4.1 Flash) reached the same malware conclusion using about 17 times the reasoning tokens (89,902 vs 5,178). Limits: context (the 67 KB binary used about 163,000 tokens; a 10 MB program would need about 24 million), small programs, single runs, one malware sample, and no released code or prompts found in the text. Posted 18 November, so inside the 7-day window. Built by: George Xenos and Sotiris Giannopoulos · Artefacts: write-up · Signal: 198 HN points. Source: https://sgiannopoulos.github.io/blog/machine-code-programming/ (discussion: https://news.ycombinator.com/item?id=50546587)

- noclip: a playable neural world model of the Backrooms — A 211M-parameter causal transformer, trained from scratch with flow matching on latents from a DC-AE autoencoder, generates each frame (512x288, 10 fps) from the last 24 frames plus key/mouse input, with no game engine behind it. Training data came from a procedural 18-level simulator with a scripted explorer; training used 6-11 RTX 5000 Ada GPUs for two days. Reported 47 ms per frame on an RTX 5000 Ada against a 100 ms budget; frames match the simulator at 26.7 dB PSNR for the first second, falling to 17.3 dB by twelve seconds. Rooms stay coherent for tens of seconds, but places are remembered only briefly (walking back usually yields a different room), doors and entities are unreliable, and CPU play takes 2.5 s per frame. Needs an NVIDIA GPU with about 4 GB free. Created 21 November. Built by: Yelar · Artefacts: code and weights (Apache-2.0), model on Hugging Face · Signal: 2 stars, 2 HN points. Source: https://github.com/Yelar/noclip (discussion: https://news.ycombinator.com/item?id=50594070)

- Pencil: an LLM writes a whiteboard lesson as JSON, the browser draws and narrates it — The planner (DeepSeek by default, stdlib-only, Anthropic optional) emits strict JSON `beats[]` with narration, drawing operations and a cue giving the narration word index where each element appears; a validator with a repair loop checks it and a player draws SVG step by step using browser speech synthesis, and it reports tokens and cost per lesson. The interesting part is the schema-plus-validator split that keeps the model from emitting pixels. Tests use a scripted fake model; only DeepSeek has been run live, and it has two commits. Created 21 November. Built by: VBS2004 · Artefacts: code (MIT), live demo · Signal: 3 stars, 3 HN points. Source: https://github.com/VBS2004/pencil (discussion: https://news.ycombinator.com/item?id=50592137)

- Frostwind: a pixel-art "world compiler" where the LLM writes tables, not pixels — Scenes are derived from analytic terrain fields and explicit models of physics, life and craft, with sprites stored as material, normal, occlusion and thickness channels and a final quantisation to a locked palette; the LLM only fills schema-checked tables. Physical scale is explicit (26 px = 1.70 m, so a 1.18 m roe buck is 20 px) and a frame gate checks GPU output uses only the declared palette. Five playable worlds, JavaScript/three.js; no night lighting, dialogue or saves, and "visual review remains the authority" per the README. Two commits. Built by: Trinity Labs Pte. Ltd. (trinity-works) · Artefacts: code (MIT), browser build · Signal: 85 stars. Source: https://github.com/trinity-works/frostwind

- Musset: a Mac novel-writing app whose AI editor "never writes a word for you" — Swift/SwiftUI with a Rust typesetter on Typst, chapters as plain Markdown with version history, PDF/EPUB output; the AI leaves margin notes and answers questions via your own Claude Code or Codex account (no provider keys held, works with AI off). Apple silicon, macOS 14+, beta (one-time USD 9.90 from 1.0, optional EUR 4.99/month sync), and a daily update check sends an anonymous counter. Built by: Musset-App organisation (unnamed) · Artefacts: code (GPL-3.0) · Signal: 11 stars. Source: https://github.com/Musset-App/musset
