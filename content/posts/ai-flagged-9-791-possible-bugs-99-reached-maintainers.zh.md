ImageMagick 由 2 人负责维护。在这次试点中，他们收到 22 份安全报告，其中一份乍看很像以前见过的类型。报告摘要表明并非如此，还直接指出了具体代码行。维护者在 15 分钟内就推送了修复。ImageMagick 的一位维护者事后表示，通常情况下，一份安全公告“平均需要约 30 分钟到 1 小时来阅读、理解并完成修复”。

这点时间节省并不算多，而且由受益方自己讲述。它处在一整条流程的末端，而流程起点的规模要大得多。

## 试点做了什么

11月17日，GitHub 的 Ashley Wolf 和 Gregg Cochran 介绍了与微软（Microsoft）在 6 个开源项目上合作开展的试点，涉及 AutoGPT、Caddy、Express、FastMCP、ImageMagick 和 Netty。微软的扫描系统 Codename MDASH 配合其 MAI Cyber 模型，逐一扫描了各项目的代码库，并针对发现的问题给出修复建议。结果图表显示，6 个项目合计标记出 9,791 个潜在问题。

这些结果都没有直接发给维护者。GitHub Security Lab 开发的 AI 分拣智能体（agent）先剔除重复项、核查有效性，只保留高影响漏洞。随后，微软 FORGE Lab 的研究人员逐条人工复核了剩余结果，7 名研究人员在每个项目上大约投入了 2 天时间。最终通过 GitHub 私密漏洞报告渠道送达维护者的共有 99 份报告，每份都附带概念验证和修复建议。换算下来，大约每 100 条原始发现，最终只形成 1 份报告。

修什么、何时修，均由维护者自行决定。截至 11月15日，维护者已修复其中 55 份报告涉及的问题，其中 14 项修复已经随版本发布。Caddy 维护者在一周内修复了收到的全部 22 个问题。AutoGPT 维护者刚上线一项新的检查逻辑，但存在缺陷；3 天后报告送达并准确指向出错的代码行，他们在一天内写出修复代码，不到一周就部署到了生产环境。

## 试点要应对的报告洪流

这项试点回应的是维护者们 2 年来一直在反映的问题。1月26日，curl 项目负责人 Daniel Stenberg 发文宣布，该项目的漏洞赏金计划将于 1月31日终止。他写道，该计划自 2024年下半年开始缓慢走下坡路，“在 2025年急剧恶化”，伴随着“AI 垃圾报告激增”。他表示，2025年之前，提交的报告中超过 15% 最终确认为漏洞。而到了 2025年，这一比例跌破 5%：“20 份里连 1 份真的都不到。”

近 7 年间，该赏金计划为 87 个已确认漏洞支付了超过 10 万美元。Stenberg 称，在噪音涌入之前，这一计划一直是成功的。他停止发放赏金，以消除提交“凭空捏造的谎言”的动机，并告知报告者改用 GitHub 私密漏洞报告渠道——这与此次试点使用的是同一渠道。他公布的 HackerOne 过去一年数据显示，curl 收到的报告量急剧上升，而 Ruby、Node 和 Rails 基本持平或略有下降。他表示，其中原因有待进一步推测。

GitHub 的文章援引 Log4j 维护者 Christian Grobmeier 的看法点出利害所在：防守开源的 AI 必须强于攻击开源的 AI。GitHub 自身的判断是，AI 让发现潜在漏洞变得“既快又便宜”，但修复漏洞仍然需要人的判断，而在开源领域，这种判断由维护者作出。一位 Netty 维护者用自己的话说：“发现漏洞已不再是我们的瓶颈。修复它们才是难处。”

## 筛选的成本

试点数据显示了成本流向何处。模型产出了数千条候选结果，文章没有披露这一步的费用。从数千条筛到 99 份，先要依靠 AI 分拣智能体，再由 7 名研究人员组成的团队在每个项目上投入约 2 天时间。GitHub 直言，“试点之所以奏效，是因为每一步都有人细致工作，而这项工作目前还无法规模化。”

因此，负担并没有消失，只是转移了。过去，维护者需要自己阅读扫描器的输出，判断哪些问题属实。在这次试点中，微软团队先做了审查，只把过关的结果交给维护者。GitHub 由此提出了明确规则，适用于任何用 AI 扫描他人代码的人：每条发现都要对照项目已知问题和安全策略核查，私密提交报告，附上修复建议，并由维护者掌握处理节奏。

解读这一结果需要保持审慎，GitHub 自己也列出了几点原因。按其说法，6 个项目只是“小样本”。这 6 个项目都曾入选 GitHub Secure Open Source Fund——该基金为每个项目提供 1 万美元资助和安全培训——因此它们原本就与如今进一步提供支持的这家公司关系密切。总结出的经验来自这些项目选择分享的内容。99 份报告中修复 55 份只是某一时间点的统计，并未说明尚未关闭的 44 份报告情况如何，也没有说明修复它们还要多久。文章同样没有说明，最初的 9,791 条结果中有多少是误报、有多少重复，也没有交代分拣环节可能漏掉了多少真正的漏洞。

## 下一步走向

GitHub 表示，将为每一个曾入选该基金的项目提供 AI 安全扫描，扫描结果在提交报告前都会经过核查，并向这些项目提供 GitHub Copilot Max。公司还将把试点经验融入私密漏洞报告和安全公告功能。GitHub 补充称，维护者还需要能在私密复刻仓库（private fork）上运行持续集成（CI）测试，并能使用具备网络安全能力的模型，以便在修复前后测试概念验证。

支撑扫描的模型也在更新。就在 GitHub 发文当天，微软发布了 MAI Cyber 2 Flash，而此前的试点使用的是旧版模型。微软称，新模型在 CyberGym-E2E 基准测试中的得分为 92.3%，高于 GPT-6 Astra 的 91.5%，单任务成本不到后者的 2%；这项测试由微软自行运行，在 905 项任务中排除了 92 项。该模型将于 12月中旬起专供微软旗下安全产品使用，其中包括 MDASH。扫描成本下降意味着会产生更多结果。按试点的比例算，每多出 100 条结果，依然需要有人来审读。

GitHub 在文章临近结尾处引用了 AutoGPT 维护者的话，同样指向这一方向：推出新功能越来越容易，未来维护软件“最终可能归结为谁足够重视安全管理”。对 ImageMagick 团队而言，这次试点归结起来就是 22 份报告、其中一份看似熟悉的问题，以及一刻钟的时间。
