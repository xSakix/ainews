## Local models and agents

Ternary Bonsai 2.5 27B, a ternary 27B model that fits in 5.9 GB and runs 204 tokens/s on an RTX 4090 — PrismML released an upgrade to its Bonsai 2 27B on 24 November, built on Qwen3.8 27B and aimed at agentic coding and multi-step tool use on local devices. On the company's own evaluation SWE-bench Verified rises from 60.8 (Bonsai 2) to 75.6, against 80.6 for the full-precision Qwen3.8 27B base; AppWorld goes 51.2 to 90.5 (base 93.2) and Terminal-Bench 2.1 52.8 to 60.1 (base 70.8). Generation speed with MTP is 204 tokens/s on a consumer RTX 4090 and 291 tokens/s on an H100; it runs via llama.cpp (NVIDIA, Intel) and MLX (Mac, iPhone, iPad). Caveats: all numbers are PrismML's own (methodology is in a whitepaper not checked here), the base model still wins on most tasks, LiveCodeBench v6 slipped slightly (83.8 to 83.0), and the page does not define the ternary method or give context length. A company release rather than an individual's project, but it is the day's main local-model item (HN: 358 points). What is new versus earlier Bonsai coverage: the agentic-coding gain at an unchanged 5.9 GB footprint. Built by: PrismML (Caltech spin-out) · Artefacts: weights (Apache-2.0), whitepaper · Signal: 358 HN points. Source: https://prismml.com/news/bonsai-2-5-27b

PiPod, a coding agent that runs entirely in a browser tab on a local model — The Show HN project runs Google's LiteRT-LM compiled to WebAssembly on WebGPU, with the demo using Gemma 4 E2B (Apache-2.0 weights downloaded once from Hugging Face and cached in the browser). The agent, "Little Coder", is built on a fork of the Pi harness and works inside BrowserPod, a Node.js Linux-like sandbox in the tab: in the demo it scaffolds a Vite app, runs npm install and npm run dev and opens a preview. The page warns that smaller models are "less reliable at tool calls", it needs a WebGPU browser, and full internet access needs a key not included in this build. No benchmark is given; it is a working demo. Built by: apignotti (BrowserPod) · Artefacts: live demo · Signal: 2 HN points. Source: https://pipod.browserpod.io/

rhebok, a local memory and retrieval layer for coding agents, written in Rust — Indexes folders you choose (notes, papers, clippings, past Claude Code and Codex sessions) and injects passages into prompts through a hook only when they pass a confidence gate; also exposes an MCP search tool, durable cross-session memories and a local dashboard. Embeddings run through Ollama with a roughly 640 MB model (an optional 2.5 GB model distils finished sessions into memories); retrieval fuses vector, keyword and link-graph results. It works with Claude Code, Codex, Gemini CLI, Cursor and Claude Desktop. The comparison table against claude-mem, mem0 and others is the author's own, and the repository is brand new (1 star, 35 open issues); needs Ollama, macOS on Apple silicon or Linux, Windows only via WSL. Built by: Stellenbosch Technologies (formerly "br8n") · Artefacts: code (AGPL-3.0) · Signal: 1 GitHub star, 1 HN point. Source: https://github.com/Stellenbosch-Technologies/rhebok

## Open-source projects and tools

Hyper Elements, a React library that lets agents emit emails, PDFs and images with fewer output tokens — From the team behind Unlayer: typed React components rendered server-side to email HTML, responsive web HTML, PDF and PNG/SVG, plus a CLI that checks HTML emails and previews them in Outlook, Gmail and Apple Mail, and generated GUIDE.md/REFERENCE.md and validate()/outline() functions for agents. Its benchmark reports a median 3.4x fewer output tokens than React Email (about 70% fewer; the page itself says "3.4x", the 70% is the Show HN title and our arithmetic) and 1.8x fewer than Canvas 2D for images. Caveats: output tokens only, not total cost; five briefs per category and 16 to 20 runs per approach; email emulator accuracy is 98% against real clients; the benchmark is the authors' own. Built by: Unlayer team · Artefacts: code (MIT), benchmark code · Signal: 519 stars. Source: https://github.com/hyper-elements/hyper-elements

Brickie, durable agent sandboxes in your own AWS account or Kubernetes cluster — Each sandbox is a container with a shell and workspace; every call that changes the workspace creates an immutable snapshot (stored in S3, GCS or Azure) that can resume or fork a new sandbox. Calls run as Hatchet tasks so they are retryable and observable; Kata, gVisor and AWS Nitro runtimes are supported, and the Go provider runs in FIPS 140-3 mode. It is beta (API may change before 1.0) and needs an object store and a Hatchet instance; made by a company whose product it feeds. Built by: hatchet-dev · Artefacts: code (MIT) · Signal: 119 stars, 28 HN points. Source: https://github.com/hatchet-dev/brickie

MyGraph, long-term agent memory as a citation-enforced knowledge graph, written by Claude Code agents — A single Rust binary over SQLite with 13 MCP tools and a REST API; writes without a citation are refused by default, wrong facts are retracted rather than deleted, and a small multilingual embedding model runs locally. The spec and conformance vectors are the contract. Self-reported benchmarks with GPT-6.1 Terra: LongMemEval 0.90 vs 0.86 correct for reading the full source, at $0.015 vs $0.095 per question; HotpotQA F1 0.80 vs 0.82 direct. A 3-hop graph query is far slower than Neo4j (64 ms vs 1.6 ms on LDBC SNB scale 0.1, unaudited). Working prototype, draft spec, one server per data folder, only claude.ai tested as a cloud client. Built by: dieron (with Claude Code agents) · Artefacts: code (MIT or Apache-2.0) · Signal: 2 stars. Source: https://github.com/dieron/mygraph

agent-tool-result-reducer, shrinking big JSON tool results without silently dropping data — A zero-dependency Python library: returns results under a character budget unchanged, otherwise drops the widest fields, then cuts only at whole-item boundaries, and adds a `_meta` block telling the model how many items were included, dropped and available. Examples: about 100,000 characters down to 1,506 keeping all 25 items; the author's motivating anecdote is a 77,539-character response truncated mid-object that silently lost 9 of 11 records. It is not lossless, budgets are characters not tokens, and it is v0.1. Built by: AryabhattaLabs · Artefacts: code (MIT), PyPI · Signal: 4 stars. Source: https://github.com/AryabhattaLabs/agent-tool-result-reducer

Genesis, a CLI and skill that maps a codebase's business flows and flags which of an agent's changes are untested — Works with Claude Code and Codex: the agent reads the code, but each step must quote lines that the CLI verifies against a frozen repo snapshot, so mismatches are rejected; for Python the CLI parses the code itself. The CLI calls no model and runs nothing. On 10 commits from 5 open-source Python projects, Claude Code's correct test-coverage verdicts rose from 79% to 88% and flagged under-tested changes from 8% to 38%; for Codex the share of named entry points that were correct fell from 71% to 54%. The authors caution the sample is small and answers were scored by language models. Built by: GenesisAgentInfra · Artefacts: code (Apache-2.0) · Signal: 70 stars, 13 HN points. Source: https://github.com/GenesisAgentInfra/genesis

evidence-judge, an OpenCode V2 plugin that builds research dossiers where every claim needs a quoted excerpt — `/judge <request>` has researchers collect excerpts into a ledger, 2 to 5 isolated critics review it without seeing each other, and a binary PASS/FAIL judge gate (at most two retries) decides what counts; failing claims are marked pending or excluded, and fetched page content is treated as data. Design-only claims, no evaluation; isolation costs extra subagent tokens and time; Windows untested, not on npm. Built by: yoAlves · Artefacts: code (MIT) · Signal: 4 stars. Source: https://github.com/yoAlves/evidence-judge

HippoMaps, natural-language map search with no LLM — The Show HN author says query interpretation is a deterministic parser: a word list of brands, sports and OSM tags gives the "what", the Photon geocoder gives the "where", and the result is translated to Overpass QL, handling proximity, between-two-places and stacked conditions. Search is in Rust and Go and published as `overpass-search`; the whole stack runs on one 4-core 2019 AMD server with 64 GB RAM (about 3 TB of SSD needed for the full setup, so no offline mode yet); GPL-3.0. Commenters found misparses ("cheap coffee" returned Chinese restaurants, "dispensaries" returned pharmacies). Useful as a counterexample to defaulting to an LLM. Built by: Show HN author (Zurich) · Artefacts: live app, code (GPL-3.0) · Signal: 142 HN points, 52 comments. Source: https://news.ycombinator.com/item?id=50561199

Hermit CRM, a free CRM for solo founders whose data is Markdown in git, readable by agents over MCP — Deals and prospects live as plain files, reachable through a web app, a CLI or an MCP server, so an agent can read and update them without an API; the author asks Claude who has not been followed up with. macOS-first, no telemetry. A commenter asked how two agents editing the same deal file are handled and got no answer; another doubted the project's depth. Built by: gijsbos · Artefacts: code, web app · Signal: 49 HN points. Source: https://hermitcrm.io/

## Experiments, demos and write-ups

Looped Weight-Space Programming: Claude hand-wrote tiny transformers that solve long algorithmic tasks exactly — A group at MBZUAI (Claude Opus 5.5 is listed as co-author) had Claude set transformer weights directly, with no training, where one block loops so bigger problems need more passes. The maze transformer has 19,936 weights, built in one Claude Code session of 39 minutes for about $19 in tokens. Reported results: Maze-Hard 30x30 solved 100% versus 26% for Claude answering directly, and 0% for the same architecture trained from random weights on 1,000 mazes; the same weights solved 60x60 and 100x100 mazes; Tower of Hanoi at 20 disks (1,048,575 moves) 100% with 3,686 weights; Sudoku-Extreme 100% of 141,040 puzzles (best trained model 98.96%). Caveats: results are the authors' own, the maze program was only checked up to 45x45 by Claude, and the page's own charts disagree on the best trained baseline (99.8% vs 93.5%). It builds on Weight-Space Programming (MIT CSAIL), already covered earlier. Built by: Elsayed, Heakl, Shaker, Khan, Khan (MBZUAI) · Artefacts: code and weights (MIT), demo, Hugging Face Space · Signal: 99 stars. Source: https://github.com/mbzuai-oryx/LoopedWSP

Porting a Cayley-graph solver from A100 CUDA and JAX to TorchTPU, with agents doing the work — Andrey Lukyanenko moved a 3.4M-parameter beam-search solver for the CayleyPy Tetraminx competition to Google's TorchTPU, letting Claude Code and Codex implement and profile while he chose what to measure. Training on 4 TPU v6e went from 234.8 s/epoch (first port, 1.65x slower than the A100's 142.7 s) to 132.0 s after fused eager mode and einsum attention (about 1.08x faster). Beam search on 8 v6e chips ran 1.02 s per level versus 1.27 s for JAX (about 25% faster) with the same 185 moves, but only about 10% faster on Kaggle's v5e-8. Lessons: static shapes matter, a Flash-attention default padded short sequences (disabling it made a level about 4x faster), and a tie-ordering dedup bug surfaced only after the backend changed. Small samples (6 to 10 puzzles); JAX stays his main solver. Built by: Andrey Lukyanenko · Artefacts: write-up, Kaggle notebooks (free TPU), upstream issue torch_tpu #6304 · Signal: 72 HN points. Source: https://andlukyane.com/blog/cayley-graphs-and-torchtpu

Strict MCP tool schemas rejected 10 of 10 bad calls; loose schemas rejected none — A small lab repo compares a deliberately loose and a strict schema for a notes MCP server. The "10/10 vs 0/10" figure is a deterministic audit, not model trials: v1 silently accepted all 10 adversarial calls (three mutated the store), v2 rejected all, and v1 returned about 5.5x more result bytes on 16 ground-truth calls. Model trials (small local open models, unnamed, single-shot, temperature 0, 32 graded trials) are not broken down in the README, and a cheap lexical confusability metric scored v2 worse, which the author flags. Built by: ranadhir19 · Artefacts: code (MIT) · Signal: 2 HN points. Source: https://github.com/ranadhir19/mcp-server-lab

Terminal Tasks Open, 30 hard terminal tasks where the best agent passes 66.7% — Vetto published tasks with hidden verifiers on the Harbor framework, each admitted only if frontier models fail it in most trials. Leaderboard (the vendor's own, November 2026, 15 configurations): GPT-6.2 Astra with Codex CLI 66.7% (25 of 30), Claude Fable 5.2 with Claude Code 56.7% on one trial per task, Gemini 4 Carbon with Antigravity CLI 54.4%; several models score 0 to 4%. Caveats: only 30 tasks, wide intervals, agents got 24 hours per task against a default of eight, and the tasks carry a canary string. Built by: Vetto · Artefacts: tasks and leaderboard (Apache-2.0, also on Hugging Face) · Signal: 3 stars. Source: https://github.com/vettoai/terminal-tasks-open

DeltaOS Gym, six Linux and eBPF tasks graded by tests, simulated crashes and proofs — Each task asks for one change while preserving stated behaviour (for example a crash-safe file replace, or detecting an 8-bit overflow in IPv6 routing code). On Linux 7.1.4 the graders rejected all 71 known-wrong solutions across 355 runs and accepted correct alternative implementations in 85 of 85 runs, so the graders are checked against both sides. No model scores are reported; needs Docker and Harbor; no limitations section. Built by: Yossi Eliaz · Artefacts: tasks and graders (MIT, v1.0.0) · Signal: 1 HN point. Source: https://zozo123.github.io/deltaos-gym/

PlaceBench, 150 questions about real places in 121 cities, with Google's Ask Maps scoring 49 of 100 — VOYGR published questions, answer keys and grading scripts (CC BY 4.0). Scores: Dots 92 (95% CI 89 to 96), Muse 83, Claude Duet 79, Instinct 76, Grok Bot 73, Ask Maps 49 (36 to 61), with Ask Maps wrong on 30 of 150 answers. Caveats: VOYGR sells tools for agents working with places; one run in one week; an LLM grades (Claude Opus 5.5, and a second model agreed on only 48 of 60 regraded answers, while Claude Duet is built on Claude); 27 keys rely on Google Maps. Built by: VOYGR · Artefacts: data, keys, scoring script · Signal: 10 HN points (posted 18 November). Source: https://github.com/voygr-tech/placebench

Foolscap, a writing app that reads your book and never writes for you — Highlights characters, threads and unresolved questions in a sidebar and keeps memory across a whole work, with an agent you can question; the author's stated aim is to avoid atrophy of writers' thinking. Commenters raised privacy (training on manuscripts; the author says everything is now encrypted and there is a "may read this book" setting) and workflow friction. Product with a free tier, stack not described; the angle is a design choice, not a technique. Built by: David (solo) · Artefacts: live app · Signal: 133 HN points, 96 comments (19 November). Source: https://foolscap.works/
