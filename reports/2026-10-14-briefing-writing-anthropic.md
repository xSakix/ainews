## Deep dives and technical write-ups

- Redesigning source control at Anthropic — Anthropic's engineering team explains why merges grew from about 2,500 a day in May 2026 to over 30,000 a day in September, and why git stopped scaling for a repository whose main-branch history is near 100 GB and which is checked out about 25 million times a day for CI. Their replacement, Scion, assumes clients (mostly agents) are always online: the server computes blame, merges and rebases, there are no packfiles or refs to move, and a changeset is a write-ahead-log entry with content-addressed blobs. A team of seven migrated the monorepo in five months, and the post notes the heavy use of adversarial review and its tendency toward over-engineering. Worth reading as the first detailed account of what agent-scale developer infrastructure looks like. Simon Willison's link note (13 October) adds a chart of Anthropic model releases against merge volume. Author: Anthropic engineering team (Scion engineers) · Format: deep dive · Length: about 15 minutes. Source: https://www.anthropic.com/engineering/redesigning-source-control

- Running RAG with a (small) language model in the browser — Bart de Goede built an "ask my blog" feature (static-embedding retrieval plus a model on WebGPU via transformers.js) and graded 45 questions with a model judge, with 20 grades hand-checked (16 of 20 agreed). Result: every off-the-shelf model under 350 MB was faithful on at most 3 of 30 answerable questions and invented an answer for 13 to 15 of the 15 unanswerable ones; Qwen3-0.6B (579 MB) managed 15 of 30, Gemma 4 E2B (3.1 GB) 28 of 30 and Claude Haiku 5.5 via API 27 of 30. A useful measured reality check for local, in-browser agents, including the quirk that some q4 ONNX builds are larger than q4f16 because the embedding table stays 32-bit. Author: Bart de Goede, software engineer (personal blog) · Format: deep dive · Length: about 13 minutes. Source: https://bart.degoe.de/rag-with-a-small-language-model-in-the-browser/

- Improve TTFT for multi-turn agentic workloads with bi-directional KV transfer in vLLM — In prefill/decode disaggregated serving the KV cache normally flows one way, so the prefill node recomputes earlier turns of an agent conversation. The post adds transfer back from decode to prefill (NIXL connector changes, a KV-cache-aware router, block-retention TTL, a recompute threshold) and reports up to 1.6x lower time to first token on Qwen3-32B and 3.3x on GLM-5-FP8 on a 1P1D AWS P5en setup, with step-by-step reproduction instructions. Results are the vendor's own benchmark and depend on workload. Author: Sunita Nadampalli, AWS (vLLM blog) · Format: deep dive · Length: about 17 minutes. Source: https://blog.vllm.ai/2026/10/12/bidirectional-kvxfer-multiturn-agentic-workload.html

- Parsimony: which AI coding agent changes the least code? — An independent benchmark layer that takes the patches SWE-bench-style benchmarks already publish and counts syntax "coding units" (statements, calls, comparisons, names, literals) rather than lines, subtracting deleted code, then ranks models by net units added. The author is explicit about limits: size is not quality, models that write more code also solve more (Spearman 0.33 to 0.60 on boards with 26+ models), and only Python is measured; data and code are on GitHub. It makes verbosity of coding agents a measurable quantity. Show HN, 13 October. Author: anonymous maintainer (La5u on GitHub) · Format: benchmark investigation with interactive leaderboard · Length: about 5 minutes. Source: https://parsimony.lasu.dev/

## Prompting and context techniques

- Enforce agent conventions with a pre-commit hook that injects a corrective prompt — From the Huntley essay above, as quoted by Simon Willison: when an agent ignores a project's diagnostics (observability) library despite AGENTS.md, write a pre-commit hook that checks the git diff for direct calls to the observability modules, fails the commit and injects a prompt telling the agent to use the library. Huntley reports it went to "ten out of ten" on his own project; this is one practitioner's anecdote, not a controlled test. The pattern, deterministic check first and instructions second, is easy to copy. Author: Geoffrey Huntley (quoted by Simon Willison) · Format: technique note · Length: 1 minute. Source: https://simonwillison.net/2026/Oct/13/geoffrey-huntley/

- How Anthropic's dynamic workflows coordinate Claude agents — Report from the AI Engineer New York session by Anthropic's CJ Avilla and Harrison Stall on "flows" in Claude Managed Agents (the feature launch itself is already covered earlier; the new material is the practitioner detail). Claude writes an orchestration program that launches agents in phases and collects results, for example a scan phase over isolated-context agents followed by a review phase. Stated practice: control agent count with evals and lower defaults, set a session budget because the model does not know its budget, subagents share a filesystem but cannot message each other through the API, and the "dreaming" research preview can reorganise a memory store to improve repeated flows. Flows cost much more than a single agent; the speakers claim they find more detail. Reported by a journalist, so these are the presenters' claims. Author: Richard MacManus (Latent Space), reporting on Anthropic staff talk · Format: conference report · Length: about 5 minutes. Source: https://www.latent.space/p/claude-dynamic-workflows
