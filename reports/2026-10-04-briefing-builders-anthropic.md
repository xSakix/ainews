## Local models and agents

- Mingbird v1.9.x — a local-first agent harness for 2–9B models on ordinary laptops with integrated graphics — Mingbird wraps Ollama in an agent loop where the harness does what small models cannot: it runs the tests and feeds back exact failures, auto-backs up every edit, breaks tool-demo loops, and enforces a fixed 797-token tool prefill (CI fails any change that grows it). The author's own 288-cell benchmark (4 harnesses × 4 open models × 18 tasks, all cells published as CSV) reports the same 2B model scoring 0.821 in Mingbird against 0.017–0.271 in three other harnesses. The author also reports that swapping the harness under a frontier model moved scores from 0.997 to 0.478, and that between intact harnesses the model matters more. The author's own benchmark (LRAB-288) is self-built and not independently replicated. What is new in the window: v1.9.1 (1 Oct) bundles bilingual voice input, a `run_python` tool and six general skills; v1.9.2 (2 Oct) fixes Ollama model-directory handling on Windows. The Show HN was posted 30 Sep. Built by: Mingbird (HN user, individual or small team) · Artefacts: code (Apache-2.0), reproduction guide in `benchmarks/reproduce_one.md`, per-cell data · Signal: 5 points on HN. Source: https://github.com/Mingbird/Mingbird-agent

- where-next (`wn`) — ask a repository "where is X?" and get the three files to open, using a small model fine-tuned on commit history — The tool indexes a repo, learns from its git history and returns ranked files in roughly 80–100 ms per warm query. The author says the model was fine-tuned on about 1.1M (task → files actually changed) pairs, downloads about 1.2 GB, and says "no confident hint" when scores fall below a calibrated threshold. It ships as a CLI and an MCP server, and `wn setup` installs a skill and hooks for Claude Code, Codex and Cursor. The demo replays real bug-report titles on a kubernetes clone, with the file each fix changed ranked first. The repository's changelog shows releases 0.1.1 to 0.3.0 on 30 Sep. The accuracy figures are the author's own and `wn bench` replays past commits on your own repo to check them. Built by: HN user alukin · Artefacts: code and releases, install script, docs; licence badge present, not verified here · Signal: 6 points on HN (Show HN, 30 Sep). Source: https://github.com/andreylukin/where-next

- Jeffy — small classifiers that run and retrain on a plain CPU, including one that plays Doom — Jeffy is a pip/uvx-installable collection of 14 pretrained classifiers whose weights are logistic-regression coefficients: SMS spam (99.1% test accuracy), Banking77 intent (94.3%), AG News, SST-2, a 151-class out-of-scope intent set and more. The Doom classifier reads 24 numeric game-state features and picks fire/turn actions. The README reports 100% test accuracy for it, which says little about how it plays, so watch the demo GIFs. A local playground is included, and a public one was set up in the HN thread. It is an alpha (v0.1.0-alpha.11) and sits in the current wave of Jev-style "decision model" projects but uses classical classifiers rather than a fine-tuned LLM; an HN commenter compared it to a Markov-chain bot, and the author asks which tasks people find useful. Built by: Nico Brenner (HN user nico) · Artefacts: code, playground, GIF demos; licence not verified · Signal: 8 points on HN (Show HN, 3 Oct). Source: https://github.com/nicobrenner/jeffy

## Open-source projects and tools

- Rhun — an open-source code editor with an x86-64 assembly core — Rhun is a small editor for Linux, Windows and Apple-silicon Macs with Vim mode, a terminal, Git diffs and a panel for Claude Code or Codex sessions. The editor and pixel renderer share an x86-64 assembly core. For Apple silicon, a build-time translator converts that core to AArch64, with separate platform adapters. The latest release drafts commit messages with a local Ollama model or an existing Claude Code / Codex subscription. The author's stated goal is to add as few features as possible and hold launch time, memory and disk footprint constant. It is a solo, early project. Built by: solo developer (HN user, Show HN 1 Oct) · Artefacts: code (MIT per the post), downloads at rhun.app · Signal: 61 points, 49 comments on HN. Source: https://news.ycombinator.com/item?id=49926726

- Enki — write GPU compute kernels as ordinary Rust functions on stable Rust — A `#[nam]` attribute marks a standard Rust function, which Enki compiles just-in-time to GPU code over Vulkan 1.3 with buffer device addresses (no descriptor sets) or runs unchanged on CPU threads via Rayon. The same function can be unit-tested on the CPU without a GPU in CI. A dependency solver derives the minimal set of Vulkan barriers automatically, and a runtime borrow check detects data-race hazards at dispatch; the README says it makes no formal soundness claim. The demo is a real-time SDF raymarcher where the Space key switches execution between GPU and CPU. Not LLM-specific, but relevant to people writing their own inference kernels. Built by: enki_runtime (HN account, Show HN 2 Oct) · Artefacts: code (MIT or Apache-2.0), crate `enki-gpu`, book, demo repo · Signal: 10 points on HN. Source: https://github.com/enkiruntime/enki

- jpm — a JavaScript package manager written in Rust, with every line produced by Claude Code — The author says it was working within a few hours and then took about five more days of the agent looping on installing popular packages and hardening for Windows, macOS and Linux. It installs through a curl script with prebuilt Linux (glibc and musl), macOS and Windows binaries and is designed to play alongside other package managers. This is a case study in how far an agent can carry a large systems project when it has a real compatibility test bed, not a benchmark, and the "fast" claim is the author's. Built by: jtwebman (Show HN 4 Oct, posted 00:11 UTC) · Artefacts: code at github.com/jtwebman/jpm and installer at getjpm.sh; licence not verified · Signal: 6 points on HN. Source: https://news.ycombinator.com/item?id=49949172

## Agents and automation

- pi pod — run the `pi` coding agent in isolated sandboxes on a server you control — Built around the open-source pi coding agent (@earendil-works/pi-coding-agent), pi pod launches sessions in per-session sandboxes ("pods") hosted by one container, with a control plane (REST API, session gateway, Postgres), a CLI, and native iOS and Android clients so you can drive sessions from a phone. Identity goes through a self-hosted Zitadel; a Docker Compose self-host install needs about 8 GB RAM. The author's pitch is a lab-neutral alternative to lock-in with Claude Code or Codex, and to per-token products such as Factory or Devin, with the harness still fully customisable. The self-hosted path is open source and a hosted service is only a waitlist; HN commenters asked what it adds over a plain container or VM. Work in progress. Built by: pipod author (HN, Show HN 2 Oct, unnamed) · Artefacts: code at github.com/pi-pod/pipod (licence not verified), docs · Signal: 77 points, 30 comments on HN. Source: https://github.com/pi-pod/pipod

- Corral — a time-limited command runner that guarantees no process the command started is still alive — Agent shell tools often kill only the direct child, so double-forking daemons that call `setsid()`, background jobs holding stdout open, and processes that ignore SIGTERM survive or hang the runner. `corral --wall 30s -- cmd` runs the command in its own cgroup v2 group and kills everything with one write to `cgroup.kill` (Linux 5.14+). Without cgroups it acts as a child subreaper and signals stragglers through pidfds, and it exits with code 120 if it cannot prove the tree is gone. It is explicitly not a security sandbox; an HN commenter noted an `ssh localhost` spawn would escape any such tracker. A small, well-scoped fix for a real failure mode in Claude Code and similar agents, written by an intern while learning Linux signals. Built by: Cardinal44 (HN user CG144, Show HN 29 Sep) · Artefacts: code at github.com/Cardinal44/corral (licence not verified) · Signal: 19 points on HN. Source: https://github.com/Cardinal44/corral

- DASP, the Durable Actor Session Protocol — a language-agnostic protocol for long-lived agent/actor sessions — The author of Jido, an Elixir actor and agent SDK, reviewed A2A, ACP and Microsoft's Agent Host Protocol and found none fit sessions that outlive a chat, since AHP centres on text chat. DASP defines durable sessions between clients and a server, with clients in Elixir and TypeScript and a server planned only for the Jido ecosystem. It lands the same week as Pi Durable, so durability for long-running agents is clearly an active design space; read it as a spec proposal, with no independent adoption yet. Built by: Jido author (HN, Show HN 28 Sep) · Artefacts: protocol site and docs (repository and licence not checked) · Signal: 18 points on HN. Source: https://news.ycombinator.com/item?id=49877270

- pi-codex-connectors — use Codex's local plugin endpoints from the Pi harness or any MCP client — The author noticed that Codex now exposes local server endpoints for all its plugins without extra auth, so one login gives access to every connector. `pi install npm:@wileai/pi-codex-connector` adds them to Pi, and `npx -y @wileai/codex-connectors-mcp@latest` serves them to any other harness over MCP. Check that this use of Codex's local endpoints is allowed by your plan before relying on it; the post describes behaviour rather than an official interface. Built by: wileai (HN, Show HN 2 Oct) · Artefacts: code and npm packages, licence not verified · Signal: 20 points on HN. Source: https://github.com/wileai/pi-codex-connectors

## Experiments, demos and write-ups

- AIKON (formerly Claude S40) — an AI chat client for 2007 Nokia Series 40 and Symbian phones — A Java ME (CLDC 1.1 / MIDP 2.0) app plus a small Go server lets a Nokia 6300 or E63 chat with Claude, OpenAI, Gemini or Grok on a 240×320 screen. The server does the model calls and web search (news, weather, exchange rates), so the phone's browser and TLS stack are not involved. The phone side adds paged reading mode, long replies fetched in parts, message actions and eight UI languages. The project was renamed from "Claude S40" once it spoke to multiple providers, and the Show HN used the old name. It's a charming hardware hack with a real architecture lesson: put all the modern parts on a thin server. Built by: Emir Karsiyakali (HN user emir; Show HN 27 Sep) · Artefacts: code at github.com/emir/AIKON (old URL redirects), video on X; licence not verified · Signal: 6 points on HN. Source: https://github.com/emir/claude-s40
