## Safety and security

- AISI shows that a safety monitor's reliability number depends on how the test attacks are made — The UK AI Security Institute's Red Team (post dated 23 Nov) tested one monitor against synthetic attacks produced in different ways. The same monitor missed between 0.2% (basic prompting, most optimised) and 23% (transcript editing, most optimised) of successful attacks, two orders of magnitude apart; in one reinforcement-learning run the miss rate rose from 0.5% to 20.8%. The monitor was an ex-production OpenAI monitor running GPT-5.4, watching a Qwen 3.8 27B agent, and the attacks were tuned against a different monitor. AISI's conclusion is that a low miss rate on synthetic transcripts can give false confidence, and that showing an attack policy is representative of future attacks is unsolved; it relies on layered safeguards (limited deployment scope, humans in the loop, sandboxing). One case study, one setup. Source: https://www.aisi.gov.uk/blog/attack-policy-selection-can-make-monitor-evaluations-misleading
- OpenAI and Cisco release Shirudo, an open-source Linux runtime for covering a vulnerability before the patch is installed — It uses eBPF "shields", signed and verified before loading, with a TPM-backed record, to block the code path an exploit needs without restarting the service; operators can test a shield before enforcing it. In OpenAI's one controlled test, a Codex-generated shield stopped an exploit attempt against a running Elasticsearch service without a restart. The post gives no performance or adoption figures and the evidence is a single vendor test. Code is on GitHub (BSD 2-Clause, BPF programs dual BSD/GPL); a technical webinar is set for 15 December. The stated goal is to let defenders and AI agents deploy shields at scale, in a week when patch lag is again visible (see the Cisco item below). Source: https://openai.com/index/introducing-shirudo
