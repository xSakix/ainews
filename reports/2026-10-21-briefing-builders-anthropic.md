## Local models and agents

- Berth: a Go daemon that makes GPU programs take turns on one card's memory — On a single consumer GPU, a chat server, ComfyUI, a voice engine and a game each grab VRAM and crash each other with out-of-memory errors. Berth is one broker per card: engines run under `berth run --as llama -- llama-server ...`, lease the card instead of grabbing it, and `berth status` shows who holds it and who waits. It can also serve the engines behind one API endpoint, so a client asks for a model and the broker swaps what is loaded. The poster runs it on one RTX 4090 with llama-swap, a ComfyUI install and OpenWebUI. The v0.3 edit parks idle engines in system RAM so a switch back skips the disk reload; the author has only 62 GB RAM and asks for testers with 64 to 128 GB, multi-GPU boxes, Windows and AMD. Windows support is marked experimental, and no timings are published in the post. Built by: Reddit user Distinct-Pie2389 (GitHub T-Crypt, individual) · Artefacts: code (Apache-2.0), releases, CI · Signal: r/LocalLLaMA post of 20 Oct (RSS timestamp 03:27 UTC); star count not checked. Source: https://old.reddit.com/r/LocalLLaMA/comments/1xahi82/24gb_is_plenty_if_your_engines_take_turns/ Repo: https://github.com/T-Crypt/berth

- Qwen3-4B with the "AI writing tics" trained out, tuned on a MacBook Air — Erik Kannike distilled the assistant style out of Qwen3-4B-Instruct with a small LoRA adapter trained on 161 filtered answers, no system prompt needed. On 40 held-out prompts his own slop detector (weighted count of em dashes, "not X, but Y", lists of three, "delve"-type words) falls from 121 to 12.5 per 1,000 words, with 68% of answers in the human range; em dashes go to zero and 30 of 30 factual questions stay correct. The write-up is candid about failures: an intermediate version scored 9.9 but wrote opinion pieces without an opinion, invented a study, and joined sentences with ", which". The teacher combined a found "assistant register" direction, a four-neuron patch and a plain-style prompt, then a second filter checked the answer did what was asked. Runs locally via `ollama run hf.co/erikkannike/qwen3-4b-deslop-v4-GGUF:Q4_K_M` (2.5 GB). All figures are the author's, from a detector he wrote himself. Built by: Erik Markus Kannike (individual) · Artefacts: GGUF weights on Hugging Face, long write-up with examples · Signal: 154 points, 81 comments on Show HN, 19 Oct. Source: https://news.ycombinator.com/item?id=50151928 Write-up: https://100toolkit.com/blog/deslop-model/

## Open-source projects and tools

- Antirion: a single-binary Rust LLM gateway with a built-in admin console, benchmarked against Bifrost and LiteLLM — It sits between apps and providers (OpenAI, Anthropic, Gemini, Bedrock, Vertex, Mistral, DeepSeek, any vLLM-style server), routing, budgeting and logging calls, with the console shipped inside the same binary. The README claims, on identical AWS c7i.xlarge machines at 5,000 requests per second, 0.53 ms median and 0.95 ms p99 overhead against 19.7 ms and 95.2 ms for Bifrost 2.2.4, while LiteLLM 1.103.1 failed every request in that run. The method is described (interleaved repetitions, medians, minimal setup), but this is the author's benchmark of a competitor's products and has not been independently reproduced. Built by: eliasbiondo (individual) · Artefacts: code (Apache-2.0), distroless image, docs · Signal: about 145 GitHub stars within four days of creation (17 Oct); no HN or Reddit thread found. Source: https://github.com/eliasbiondo/antirion

- VoidAccess: self-hosted dark-web OSINT that turns a query into an entity graph and STIX/MISP exports — A security researcher automated what he calls the unmanageable part of dark-web research: parallel collection from Tor indexes, paste sites, code forges and curated onion seeds, entity extraction (IOCs, wallets, actors, CVEs), enrichment, relationship graphs and exports to STIX 2.1, MISP, Sigma, YARA and Suricata. An LLM step is optional (`--no-llm` works), and the README describes mandatory content-safety gates that filter prohibited queries and results. Several HN commenters suspect the repo and announcement are largely AI-written; the author says only that he built it "in the wave of AI". What it finds in practice is not shown; no sample reports were posted. Built by: Katriel Moses (individual) · Artefacts: code (MIT), PyPI package, Docker Compose, demo GIF · Signal: 127 points, 13 comments on Show HN, 20 Oct. Source: https://news.ycombinator.com/item?id=50167286 Repo: https://github.com/KatrielMoses/voidaccess

- Penmentor: a pen-tablet maths mentor that marks handwritten work like a teacher — A student of calculus working in xournal++ presses a key and an agent (Claude Code, Codex or Antigravity CLI, running on the user's own subscription) circles the first real mistake, ticks correct lines, offers a ladder of hints rather than answers, and generates an interactive 3Blue1Brown-style manim animation for a boxed expression. A small xournal++ plugin passes the whole page, not just the screenshot. The demo is scripted with a fixed model answer, so it shows the interface rather than a measured accuracy; one commenter wants to try it for homeschooling. ## Agents and automation

- Lights-on software factory: a Claude Code boilerplate from a conference talk, claiming about 80% lower token spend — Gojko Adzic published the setup behind his Votito product: a container sandbox sharing only the workspace, a deterministic bash-command regulator (approve or deny with instructions, to cut approval fatigue), a PostToolUse linter hook that feeds custom rules back to the agent, a plan/implement workflow, and a script generator for multi-agent workflows. The 80% figure compares his orchestrator with bare Claude workflow execution on his own project and is not independently measured. The first comment asks how per-agent credentials are isolated, which the README leaves partly open. Slides from his GOTO Copenhagen talk are linked. Built by: Gojko Adzic (individual) · Artefacts: code and docs (repo includes a LICENSE file; type not checked), slides PDF · Signal: 17 points, 2 comments on Show HN, 20 Oct. Source: https://news.ycombinator.com/item?id=50160198 Repo: https://github.com/gojko/lights-on-software-factory

- SIwithin: run Claude Code or Codex unattended inside a folder fence and under a dollar budget — A single-file, standard-library Python tool for macOS that refuses your home folder, caps spend per run and across runs, and writes one record per run saying what it cost and whether it finished. For Claude it starts a loopback proxy that holds the real API key so the run only holds a per-run token and every request is metered and refused past the budget; Codex, which cannot be stopped mid-run, is refused unless the user accepts that. Commenters ask what it adds over built-in max-budget flags and note that the README looks Claude-written; another says telling "done" from "stopped" is the harder problem. The smoke test has only been run on Python 3.9.6, and the author says so. Built by: metahumansworld (individual, unaffiliated with Anthropic or OpenAI) · Artefacts: code (licence not stated in the README excerpt), smoke test · Signal: 8 points, 3 comments on Show HN, 20 Oct. Source: https://news.ycombinator.com/item?id=50167456 Repo: https://github.com/metahumansworld/SIwithin

- Reticle: let the coding agent drive your running app and return pass, fail or cannot-tell with a file:line — Instead of an agent declaring "done" after writing code, Reticle connects through a local service on 127.0.0.1:4400 (token paired in `~/.reticle/`) to the real app and reads what happened, replacing passwords and card numbers with [REDACTED] and offering no arbitrary page-JavaScript tool. Commenters on HN question why it is faster and more token-efficient than Playwright MCP or browser-use; the README carries benchmarks that are the project's own. It has a Discord and an npm package, and is closer to a startup product than a hobby repo. Built by: Reticle team (reticlehq) · Artefacts: code (Apache-2.0 plus FSL, per badge), npm packages, docs · Signal: 11 points, 6 comments on Show HN, 20 Oct.
