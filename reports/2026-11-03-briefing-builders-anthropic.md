## Local models and agents

tensorless: a 3-bit Qwen3.8-27B and a Pascal-specific engine for the ~$100 Tesla P100 — One-command launcher (`tensorless run ...`) that pulls a model quantised for one specific old card, the 16 GB Tesla P100, and serves it through a llama.cpp-based engine with kernels written for Pascal (sm_60). The project's own PN3 weight format puts Qwen3.8-27B in 12.1 GiB and the builder reports 30.1 tok/s short-context decode, measured on a real P100 with the published image; long-context rows are marked not yet measured. Interesting for readers pricing local inference: the hardware is cheap second-hand, and the work is in the quantisation and kernels. Performance figures are the builder's own.
Built by: iammrduncan · Artefacts: code (Apache-2.0), models on Hugging Face, design docs · Signal: 1 GitHub star (v0.1.0 released, repo created 2 Nov)
Source: https://github.com/iammrduncan/tensorless

llama-modchip: 30B sparse MoE on a CPU with no GPU, using speculative decoding — Wraps a patched llama.cpp that downloads Nemotron-3.5-30B-A3B (Q4_0) and serves it on CPU only, with a long-context cache restore and a speculative-decoding scheme the author calls Stockfish-PVS. On a Ryzen 9 9955HX with 64 GB DDR5 the README reports 18.8-20.9 tok/s decode on prose and new code, 28.6-34.5 on agent/mixed refactors and about 48 tok/s average on in-context refactoring, against a stated 4.5 tok/s baseline; it also wires Claude Code to the local engine. These are the builder's own numbers on one machine, and the headline range depends on how repetitive the text is.
Built by: synchopate · Artefacts: code (Apache-2.0), technical write-up (ARCHITECTURE.md), CPU leaderboard · Signal: 71 GitHub stars
Source: https://github.com/synchopate/llama-modchip

LiteMoE: a ~1,600-line MoE inference engine that matches vLLM on fixed batches — A deliberately readable Python engine for mixture-of-experts models that reuses vLLM's expert, attention and router kernels but owns the forward pass, KV cache and generation loop; whole decode steps run as a CUDA Graph. The README reports 108.8% of vLLM 0.32.0 throughput on an A100 and 105.3% on an L4 (Granite 1B and 3B), with a GSM8K check showing -0.9 points (CI -2.9 to +1.1) and an honest note that it has no scheduler or serving stack. A useful read for anyone who wants to see where decode overhead actually goes.
Built by: ZhuLinsen · Artefacts: code (Apache-2.0), tutorial, reproduce script · Signal: 10 GitHub stars
Source: https://github.com/ZhuLinsen/LiteMoE

kv-cache-lab: what KV-cache quantisation really saves on an 8 GB laptop GPU — A one-script measurement lab that tests the vendor claim of '50% off'. On one 8 GB GPU and one model it finds 19.5-20.8% off the total VRAM bill at 32K context (42-45% off the KV cache itself), and shows that a single linear fit is rejected (F = 2748) in favour of about 29.99 KiB/token plus a one-time ~67 MiB allocation step. The author states plainly that it measures memory only, not throughput or quality, on one setup. Raw CSVs and the script are included, so the claim can be rerun.
Built by: johnpian233-droid · Artefacts: code and raw data (licence not checked), README write-up · Signal: 1 GitHub star
Source: https://github.com/johnpian233-droid/kv-cache-lab

Llama RPC Farm: pool the GPUs in your house into one llama.cpp cluster — A web dashboard that sets up real multi-machine llama.cpp RPC clusters (peers started over SSH) and on-demand multi-model serving through llama-swap, on any mix of Linux and Windows boxes. It exposes tensor-split across GPUs, speculative decoding, KV-cache options and 128k+ contexts, plus live VRAM and temperature gauges, a per-model flag editor and an auto-tuner, and touches nothing outside its own folder. Aimed at people who own several mid-range cards rather than one large one.
Built by: dakotacookson · Artefacts: code (Apache-2.0) · Signal: 2 GitHub stars
Source: https://github.com/dakotacookson/Llama-RPC-Farm

Tarn: a native Mac app that picks the open model that fits your RAM — A SwiftUI app for Apple Silicon that reads your chip and memory, installs the most capable open model that leaves half the RAM free, and then behaves like a chat app: cross-chat memory kept in an editable local file, vision add-on loaded only when images appear, folder access that asks before every change, MCP connectors importable from Claude Desktop and skills in the same SKILL.md format. It also estimates water saved per local answer and documents the method. A good example of local AI packaged for non-technical users.
Built by: Rishab87 · Artefacts: code (MIT), docs · Signal: 5 GitHub stars

Liquid Agent: a private computer-use agent on LFM3 1.7B and LFM3 Omni 2B — A local web UI for Mac and Linux that routes everyday text to LFM3 1.7B and voice, camera and screen to LFM3 Omni 2B, with shell and file tools, a folder-scoped sandbox and three safety modes. The interesting part is 'Approve for Me', which uses a 150M-parameter classifier (Auto 150M) to approve safe actions and ask about the rest, plus an activity log recording who approved each action. Shows how far two-billion-parameter models can be pushed as an on-device agent.

The author reports about 31 seconds per compaction instead of 3 minutes and 71 of 71 facts kept versus 59 in his test. The test set is the builder's own and small, but the trick is easy to copy.
Built by: ATLAS-0321 · Artefacts: code (MIT; Python standard library only) · Signal: 3 GitHub stars

Unlocking a $25 NVIDIA CMP 100-100 mining card from 6 GB to 12 GB on Linux — A second-hand mining GPU (GP100/Pascal) sold with 6 GiB enabled now initialises with 12 GiB under the normal NVIDIA driver through a documented script. ## Agents and automation

Nomos: a Go harness that stops coding agents from cheating on tests — A 28 MB static binary that sits between your repo and Claude Code, Cursor or OpenCode: it locks main read-only with Git hooks, isolates every task in a worktree under a state machine, keeps spec tasks separate from code tasks so an agent cannot edit the spec to excuse broken code, and runs 42 structural gates (about 460 ms) before any merge. Gates block deleted assertions, skipped tests, hardcoded stubs and leaked secrets. A direct answer to a failure mode many developers report; effectiveness is the author's claim.
Built by: mgantlett · Artefacts: code (Apache-2.0) · Signal: 3 HN points
Source: https://news.ycombinator.com/item?id=50337394  https://github.com/mgantlett/nomos

Deedglass: check what an AI agent actually changed in your database — Born from an agent that reported updating 1 row while Postgres changed 301. Rules decide each tool call, then Deedglass compares what really changed (matches, doesn't match, can't check) and seals a signed record. Runs locally with one npx command; releases are checksummed and cosign-signed. A concrete take on post-hoc verification for agents touching databases and health records.
Built by: ajuxarjun · Artefacts: code (open source, licence not checked), releases · Signal: 4 HN points
Source: https://news.ycombinator.com/item?id=50337736  https://github.com/deedglass/deedglass

Skein: fail-closed orchestration for local agent swarms — Executes explicit task graphs with bounded concurrency and a persistent epoch fence: an emergency stop invalidates queued work and rejects late completions from the old epoch instead of just labelling tasks cancelled. The author calls v0.2.0 early and asks users to test the stop proof on their own workloads.
Built by: Balanov (Paritet) · Artefacts: code (MIT), architecture and security docs, benchmarks · Signal: 104 GitHub stars
Source: https://github.com/Balanov/skein

Understudy: a CPU-only proxy that distils your expensive model's repeated calls — Forwards requests to the 'lead' model, trains small CPU models on its answers per question type, lets competing designs race, and 'graduates' one only at near parity, while continuously auditing and demoting any that drift. Aimed at pipelines that ask the same narrow question millions of times. No savings figures given in the README that I could verify.
Built by: Endgame-Labs · Artefacts: code (MIT), graduation docs · Signal: 5 GitHub stars
Source: https://github.com/Endgame-Labs/understudy

sweet-search: local code search for Claude Code, Codex and OpenCode — Six-tool local search (hybrid retrieval with late-interaction reranking, a custom grep, GPU-accelerated incremental indexing) with custom ANN and MaxSim kernels. The author reports 5-33% cheaper agent runs with equal solved tasks (481 of 1,000 pooled across five model and harness combinations) on 200 held-out SWE-rebench tasks. Benchmark is self-run.
Built by: mrsladoje · Artefacts: code (licence not checked), benchmark tables in README · Signal: 3 HN points
Source: https://news.ycombinator.com/item?id=50326635  https://github.com/mrsladoje/sweet-search

Cerebellum: small model on the robot, big model only for what it can't undo — Open-source decision layer for robot fleets: each action is marked by the cost of a mistake, the robot's own model decides what it is sure of (about 65 ms on a Raspberry Pi in the demo), NVIDIA Nemotron approves irreversible actions, and decisions are journaled and synced after a network drop. One server serves a whole fleet. Demo-stage and builder-measured.
Built by: cerebellum-labs (dminglv) · Artefacts: code (licence not checked), live demo · Signal: 3 HN points

Two commands add it to Claude Code as an MCP server, with no API key or vector database. A research project; the open issue tracker lists where help is wanted.

The README reports Qwen3-4B pass@1 rising from 0.419 to 0.774 on task types it never trained on. Good teaching material; the numbers are the author's.
