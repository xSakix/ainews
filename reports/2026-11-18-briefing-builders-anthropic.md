## Local models and agents

- TrnRT: an open-source LLM inference engine for AWS Trainium — RunAnywhere built an OpenAI-compatible server that runs one model (GLM-5.3-Flash so far) on a single trn2.48xlarge. Decode runs as NKI megakernels (about one kernel per layer half), with sparse plus linear attention for contexts up to 1M tokens and a radix-tree FP8 KV prefix cache with a host-memory tier. The README claims 3.57M tokens/minute on one instance in the SemiAnalysis AgentX replay (32 concurrent agents, 1M context), a batch-8 decode step cut from 32.2 ms to 24 ms, and $0.040 per million tokens at spot ($0.167 on a capacity block). It also says outputs matched an earlier build byte for byte on 384 of 384 requests. All figures are the builder's own and the benchmarks were run on an earlier build. Built by: RunAnywhere · Artefacts: code (Apache-2.0) · Signal: 46 HN points, about 1.6k GitHub stars. Source: https://github.com/RunanywhereAI/trnrt

- inference-optimisation-skill: an agent skill that hill-climbs local LLM serving speed — A SKILL.md procedure plus standard-library Python and bash scripts. The agent computes a theoretical ceiling for the hardware, changes one thing at a time, A/B tests against interleaved controls, logs failures too, and gates every result on a long-context retrieval check. The README reports Intel Arc B390 iGPU decode from 43.6 to 53 tok/s (about 55% of its computed ceiling), 91.2 tok/s on an Arc Pro B70 against 25.0 for llama.cpp Q4_K_M on the same card, and 96–141 tok/s on an RTX 3090 with MTP. These are self-reported. The ceiling-first method is the transferable part. Built by: sybil-solutions org (individuals not named) · Artefacts: code (MIT) · Signal: about 940 stars within two days, a single commit. Source: https://github.com/sybil-solutions/inference-optimisation-skill

- SHARD: local inference with experimental LAN pooling — A Python (FastAPI) engine that runs GGUF models via llama.cpp and Hugging Face models via PyTorch, serving both OpenAI- and Anthropic-compatible endpoints. It pools VRAM and RAM across machines on a LAN, which it marks experimental, and includes a `shard fit` command that estimates whether a model fits before download. No independent benchmarks and very few stars, so treat the claims as unverified. Built by: avelone123123 · Artefacts: code (MIT) · Signal: 2 stars, 2 HN points. Source: https://github.com/avelone123123/shard

- Ferrovec Retrace: local semantic search over pages you have read — A Chrome extension on top of ferrovec, a Rust/WebAssembly HNSW vector store that persists to the browser's Origin Private File System with checksummed alternating snapshots and a write-ahead log. Embeddings use a roughly 23 MB quantised MiniLM model that runs in the browser. The author reports zero requests of the extension's own in one automated run. Type "rt" plus remembered words in the address bar. Built by: singhpratech · Artefacts: code (MIT), extension · Signal: 17 stars, 3 HN points. Source: https://github.com/singhpratech/ferrovec/tree/main/extensions/retrace

## Open-source projects and tools

- git-twig: copy-on-write git worktrees for coding agents — A Rust CLI where `git twig new` clones a nearby checkout using APFS, Btrfs or reflink-XFS copy-on-write, so parallel agent worktrees share disk blocks until changed. The README claims up to 97% less disk than standard worktrees, falls back to plain `git worktree` elsewhere, and `git twig skill` prints instructions for an agent. At v0.5.0 with 115 commits. Built by: leostera · Artefacts: code (MIT) · Signal: about 250 stars. Source: https://github.com/leostera/git-twig

- harness-profiler: see where a Claude Code session's tokens go — Hooks log every skill, subagent and tool call as JSON lines and render a call tree. It reports tokens per context split into new input, cached input and output, and whether a call shared or forked context. In the author's example run, cached input dominated the cost of a long subagent. That is one run, not a pattern, and the README lists limits (Bash edits hide Read/Edit calls, inline skills blur into their caller). Built by: afurmanov · Artefacts: code (MIT), plugin · Signal: 36 stars. Source: https://github.com/afurmanov/harness-profiler

- Machine Internet: turn a site's hidden JSON API into MCP tools — It checks about 20 common OpenAPI locations, otherwise records same-site JSON traffic in headless Chromium, has an LLM infer endpoints and condense them into at most 15 MCP tools, and serves the result over stdio or SSE. The author tested 51 sites and says about one in three works fully. Server-rendered or bot-blocking sites mostly fail. It is read-only by design. Built by: chetanty · Artefacts: code (Apache-2.0) · Signal: 4 stars, 3 HN points. Source: https://github.com/chetanty/machine_internet

- VIDEO.md: a layered text format for agents to read videos — Modelled on SKILL.md. A front-matter card with a map of per-file token sizes, then a shot timeline, topic files and per-shot files, so an agent opens deeper layers only when a question needs them. Observed and inferred content are marked differently (a tilde). It ships a JSON Schema and a Python reader and validator (`pip install videomd`). Early: 15 stars. Built by: videomd org · Artefacts: spec (CC BY 4.0), code (Apache-2.0) · Signal: 15 stars. Source: https://github.com/videomd/videomd

- Fursoy Slice-1: an open RISC-V out-of-order core that boots Linux in simulation — A 2-wide RV64IMAFDV core in SystemVerilog with a 128-entry ROB, Sv39 virtual memory and a TAGE-style predictor. It boots Linux 6.6.50 with BusyBox in Verilator, not on silicon (about 90.3M cycles, IPC 0.84). Lockstep co-simulation against sail-riscv gave 0 mismatches over 1,177 steps. The README admits the full core did not close timing at 500 MHz in Nangate 45nm (8 blocks closed). It is not an AI project, but it is a documented hardware build with inspectable verification. Built by: FURSOY (individual not named) · Artefacts: code (Apache-2.0), interactive explorer · Signal: 63 stars, 86 HN points. Source: https://github.com/FURSOY/fursoy-cpu

## Agents and automation

- Agav: a terminal coding agent built to waste fewer tokens — An experimental beta that reuses cached context, caps retries and budgets, stops unproductive repair loops and isolates subagent exploration. It claims 62.0% on SWE-bench-Live Lite and 84.7% on Terminal-Bench 2.1 (submission under review). In its cost study it spent 49.1% less than Codex at matched rates, with a 15.2 cent median per trial. The README says this is a cost result, not an accuracy claim: Agav passed 60.4% of trials against 76.6% for Codex. The page does not reconcile the 84.7% and 60.4% figures. All numbers are self-reported. Built by: prapaa-ai · Artefacts: code (Apache-2.0), methodology and data links · Signal: 26 HN points, about 187 stars. Source: https://github.com/prapaa-ai/agav

- Pulsar: one message bus for every coding agent on a machine — An MCP server and a per-machine daemon with a SQLite message log, reached over a user-only Unix socket. It delivers messages through each harness's own mechanism (Claude's per-session inbox socket, `codex queue --resume`) and can wake idle agents. It covers Claude Code, Codex, OpenCode, pi, Cursor and Gemini CLI. Peer messages are labelled as not coming from the user and cannot grant permissions. Multi-machine support is not yet built. Built by: yocontra · Artefacts: code (MIT), npm · Signal: 20 HN points, 40 stars. Source: https://github.com/yocontra/pulsar

- xcontrol: tmux groups for agents with peer messaging — A `.agents` file lists folders and agent CLIs (Codex, Copilot, Claude). `xc` opens them as tiled tmux panes and resumes sessions, and `xc send` lets agents message each other. The README warns that Codex panes bypass approvals and sandboxing by default and that messaging is not a queue. Same idea as Pulsar at a much smaller scale. Built by: faustinoaq · Artefacts: code (MIT) · Signal: 2 stars. Source: https://github.com/faustinoaq/xcontrol

- fix-with-agent: a GitHub Action that repairs breaking dependency updates — When tests fail on a Renovate or Dependabot PR, it runs the Claude Code CLI non-interactively with a $2.00 budget cap and a 10-minute timeout. If the tests pass it pushes a fix commit and posts a report of decisions, and merging stays manual. The write-up reports no measured success rate. Built by: Arnaud Renaud · Artefacts: code, write-up (11 Nov; the Show HN went up 17 Nov) · Signal: 2 HN points. Source: https://www.arnaudrenaud.com/articles/fix-deps-breaking-changes-with-background-agent/

- Solarian: a Python framework for AI-driven robots — One stack from hardware control to AI control. Robot modules run as separate processes over ZeroMQ, and the same robot class and YAML drive MuJoCo or real hardware. A vision-language-model agent harness calls robot skills as tools. Teleoperation sessions are recorded for training diffusion or ACT policies. The page does not state a licence, so check the repository before relying on it. Built by: PrimaryKey Inc. · Artefacts: code (repo at github.com/solarian-dev/solarian; licence not stated on the page) · Signal: 6 HN points. Source: https://solarian.dev

## Experiments, demos and write-ups

- Soccer-Bench: teams of LLM agents play 5v5 soccer — Five copies of a model each make a separate call every simulated second and coordinate only through short shouts heard on the next tick. The page has a leaderboard switchable between Claude and GPT, with ratings, confidence intervals and a games browser with filters for upsets. The leaderboard was still loading when fetched, so no results are reported here. The page does not name its builder. Built by: not stated · Artefacts: demo, findings write-up, code and data on GitHub · Signal: 9 HN points. Source: https://darksinian.github.io/soccer-bench/

- FrontierHarness Eval v1.1: which agent harness is best for which model — Runta, with Baseten, ran 27,280 agent runs (83B tokens) across 22 harness configurations, 5 open models and 62 terminal tasks. It reports that the model explains 92.8% of cost variation and the harness 2.3%. The best-value harness differs by model (Codex CLI ranked 1st with GLM-5.3 and 16th with Kimi-K3). 64.5% of inference cost went to failed runs, and 216 trials were flagged for reward hacking and scored 0. Limits: open models on a single provider, costs at list price. This comes from a company, so it is a vendor's own measurement, but it comes with a method and a dashboard. Built by: Runta (post by Shilin Zhu) · Artefacts: write-up, dashboard (frontierharness.org) · Signal: 340 HN points. Source: https://runta.com/blog/introducing-frontierharness-eval-v1-1/

- Action Is All You Need: small transformers trained from scratch on agent trajectories — Models of 126M to 897M parameters predict an agent's first tool call. On 314 held-out trajectories (chance 31.5%) they pick the right tool 88.2% to 95.2% of the time and the right tool with all arguments 55.4% to 72.0%. The largest used a bigger corpus, so it is not a clean point on the scaling curve. Trained on Toucan-1.5M and SWE-smith. The authors call it research artifacts, not for production. Built by: Thiago Patzdorf and James (Genesis Innovation) · Artefacts: code and weights (Apache-2.0), working paper (CC BY 4.0) · Signal: 3 stars. Source: https://github.com/thiagopatzdorf/action-is-all-you-need
