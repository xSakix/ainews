在暂存目录里，这个技能看起来平平无奇。它的 Markdown 文件描述了一个实用的快捷操作，旁边附带一个辅助脚本。但在安装程序把这两个文件复制到智能体（agent）的工作集之前，一个独立进程打开了该扩展包，追踪到某条环境变量中的密钥流向了对外网络请求，随即返回了拦截结果。

*本文开头和结尾的场景为示意性描写，其中人物均为虚构。*

ClawVet 正是为此刻而设计。这款开源扫描工具会在安装前审查智能体技能中的指令与代码。它默认离线运行，不执行扩展包内容，并可通过 OpenClaw 的安装策略强制执行判定结果。它还会记录已放行版本的权限清单，确保后续更新无法在没有再次提示的情况下悄然新增对凭据或启动文件的访问权限。

## 包装成指令的代码

智能体技能既不同于传统代码库，也不同于纯文本文档。其主文件告诉模型何时调用该技能以及如何操作，扩展包内还可能包含脚本、配置、参考文档和其他资源。这种组合带来了横跨两种语言的供应链风险：自然语言文本可以诱导智能体偏离预期，而代码则能直接借用用户账户执行操作。

ClawVet 从这两个层面同时审视扩展包。第一阶段解析主文件、代码块以及指令中引用的文件。静态规则随后排查远程代码执行、反弹 Shell、凭据窃取、挖矿程序、代码混淆与数据外泄。Tree-sitter 解析器在不运行代码的前提下，追踪 Python、JavaScript、TypeScript 和 Shell 脚本中的数据流向。其余阶段则检查未声明的程序与环境变量、高风险依赖命令以及仿冒热门技能的名称。

七个扫描阶段中有六个是本地静态分析。可选的第七阶段会将静态检测发现与覆盖缺口发送给运维人员选定的大语言模型（LLM）。语义评判器只有引用技能原文才能消除覆盖缺口，而明确的高危安全发现构成底线，评判器不得下调其风险等级。这一区分至关重要，否则“AI 安全扫描”的说法可能会掩盖源代码已被传出本机的事实。

该工具将全部检查结果归结为 0 至 100 分的评分。25 分及以下评为 A 级或 B 级并予以放行；26 至 75 分触发警告，中止无人值守安装；76 分及以上直接拦截。无论阈值如何，凡涉及已知命令与控制（C2）地址或无法读取的内容，均会直接拦截。

## 不止识别已知模式，更追踪权限变更

静态特征规则最擅长识别已有固定形态的攻击，但版本更新带来了另一类难题：一个实用技能可以先赢得信任，再在后续版本中悄悄增加一项额外权限。

为此，ClawVet 会提取技能的能力清单，包括连接的站点、敏感环境变量、凭据存储、持久化位置以及经证实的高危操作。安装门禁会将这份记录保存在本地状态中。当同一作者与标识（slug）的新版本到来时，门禁会比对前后两个版本。一旦出现新增的密钥读取、持久化路径或高危目标地址，判定就会转为警告，并明确列出新增权限。

这一设计避开了审查流程中常见的短板：审查者无需通读整个扩展包，也不必回忆旧版本原本能做什么。问题由此收窄：为何这次更新需要读取前一个版本从未访问过的密码，或连接从未通信过的主机？

不过，这种比对也有局限。ClawVet 能识别字面路径、常见占位符及多种命令拼接方式，但它并非对程序行为的通用形式化证明。其文档指出，当自然语言指令要求智能体抓取某个网页并遵照网页上的指示行事且不下载文件时，可能绕过静态分析。经过混淆的加载器以及不受支持的运行时行为同样可能落在规则之外。所谓“完整覆盖”，只代表扫描器在文件和目录限制内检查了所有可识别的引用，并不等同于安全背书。

## 实测数据说明了什么

该项目公布了在 SkillTrustBench v1.1 留出测试子集上的评测结果。该基准测试将技能表示为包含主指令文件及可选脚本、参考文档、资源和智能体定义的扩展包。其用于排行榜的 556 个案例包含 316 个恶意样本、74 个可疑样本和 166 个正常样本。

在该测试集上，ClawVet 静态门禁取得 0.660 的准确率和 0.511 的宏平均 F1。启用 Claude Haiku 5.5 作为可选语义评判器后，准确率升至 0.833，宏平均 F1 升至 0.770，恶意样本召回率达到 0.918。项目方将这些成绩与排行榜公开数据作了对比：Cisco Skill Scanner 准确率为 0.775，NVIDIA SkillSpector 为 0.712，腾讯 A.I.G（Tencent A.I.G）为 0.874。由于各方在语义配置、提示词和实现细节上可能存在差异，这份对比表仅反映单一数据集上的表现，而非普适排名。

静态模式与语义模式之间的差距，与更高的总分同样耐人寻味。代码分析可以证实某条凭据流向了网络调用，却难以判断危害取决于意图的自然语言指令。该项目的更新基准测试清楚暴露了这一弱点：在留出测试集上，其门禁与权限差异比对拦截了 95.2% 的代码注入变更，但仅拦下 36.4% 的提示词注入变更。

同一基准测试也衡量了误报带来的阻力。在良性更新中，仍有 34.1% 在门禁与差异比对的组合流程中于某一环节被拦下，尽管其中专门因权限变更触发提示的比例只有 5.1%。在 212 个独立的 ClawHub 技能上，较新版本的 ClawVet 将硬拦截从 79 次降至 37 次，同时将无警告放行从 87 次提升至 139 次。这些数据均来自项目方自建语料与标注。

更早期的测试则说明了精细标注的重要性。一组 500 个样本的语料库包含来自同一次恶意活动的 50 个技能、400 个干净技能以及 50 个困难负样本。困难负样本包括读取配置的合法 SSH 辅助工具，以及使用与攻击中相同命令的安装脚本。如果扫描器见了凭据或 Shell 命令就一概封杀，表面上看似安全，实则会让日常工作寸步难行。

## 边界明确的安装门禁

ClawVet 既可通过 WebAssembly 在浏览器中运行，也能作为命令行扫描器、预提交（pre-commit）检查或 GitHub Action 使用。其最严格的角色是安装门禁：OpenClaw 先暂存扩展包，将元数据发送给策略进程，并在提交安装前等待一条 JSON 判定结果。一旦出现格式错误的请求或扫描器故障，系统会默认拒绝放行（fail-closed）。

项目方建议用户全局安装该扫描器，而不是通过 `npx` 临时拉取最新版本。这一建议遵循其自身的威胁模型：如果在执行检查的瞬间从注册表拉取最新包，等于引入了又一次未经审查的更新。全局安装的副本则可以有计划地升级，并在升级前核验 npm 的构建证明（attestation）。

这道门禁并没有消除审查敏感智能体扩展的必要，而是将审查变成强制环节，并在拦截安装时留下可审计的依据。其公开披露的局限也将剩余的权衡摆上台面：静态模式能把扩展包留在本地，却会漏掉更多语义层面的攻击；可选的模型审查更能理解意图，但需要将选定证据发送至模型接口。

在暂存目录中，被拦截的技能最终只留作一个普通文件夹。安装程序打印出了脚本试图读取的密钥、准备发往的目标地址以及叫停复制的具体规则。智能体自始至终没有机会去判断这个快捷操作看起来有多好用。
