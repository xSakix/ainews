- Hugging Face's multi-agent series starts with a controlled test of whether agents that talk actually help — Part 1 trains four copies of a small shared model to pool private information (each holds one integer from 1 to 99; the team succeeds if at least one agent submits the full sorted list). Over 75 RL updates, training success rose from 6.6% to 82.3% (first versus last five updates) and the team solved 26 of 32 held-out problems (81.25%), while generated tokens per team fell 37.4% (about 12.8k to 8.0k); the paper it reproduces (s³) reports 93.2% after 200 updates. The framing is the useful part: more agents is not evidence of cooperation unless compared at an equal token budget (it cites Noam Brown's estimate that under 10% of OpenAI's Navier-Stokes result came from cooperation, and Anthropic's bug-finding experiment where per-million-token results were about equal on the same directories). Caveats: the task is one no single agent can solve, so it tests whether communication can be learned, not whether it beats retries; the token figures are training measurements, with no held-out efficiency numbers. - METR staff lay out how to read OpenAI's pretraining-loss curve — OpenAI's published log-perplexity for 13 base models on a fixed held-out dataset from its own codebase falls about seven times faster since early 2026 than in 2022 to 2025; at that pace the drop from GPT-3.5 to GPT-4.1, which took three years, would take about six and a half months. METR's note (the new development; OpenAI's release was covered earlier) says the acceleration is more striking because loss should get harder to reduce, but staff disagree on whether it overstates progress (overfitting, a single in-house corpus), whether benchmark scores are the better measure, or whether perplexity is a deeper measure that will be followed by real-world gains. It asks for loss on other held-out sets (such as books), the dates pretraining runs ended, and compute, labour and experiment spending, and notes Microsoft has since published its own curve on OpenAI's dataset. Caveat: METR says it has no consensus view, and the data come from OpenAI alone. ## Prompting and context techniques

- Time awareness and async input for personal agents (OpenAI developer blog, with code) — the technique: give the agent a deadline in the request ("briefing with three minutes left to review it") and turn on `experimental.time_awareness` in the Agents API so the model receives periodic time reminders, then mark the clarification tool `async: true` so the agent keeps researching while the user answers and still delivers a useful result if the question expires. In the worked example (ask at 4:00 pm, deliver by 4:12 for a 4:15 meeting) an unanswered question lapses at 4:10 and the agent writes for both possible meeting goals. Evidence is OpenAI's own demonstration on gpt-6.2-astra with no measured gain; the feature is marked experimental and in beta. Author: OpenAI developer relations (Agents API) · Format: how-to · Length: about 10 min. Source: https://developers.openai.com/blog/time-awareness-and-async-input-for-personal-agents

- Production monitoring with Codex (OpenAI developer blog) — instruction pattern for incident triage: give the agent read-only service accounts to logs, metrics, Kubernetes and deployment history (start narrow, widen on need), require evidence and citations for every claim, let an executor agent do root-cause analysis and a reviewer agent challenge it, have it propose a bounded fix with a rollback plan, and require human approval before any execution, then verify recovery from trusted signals. The eight-step loop is clear enough to copy; there are no quantitative results, only a video demo with Grafana, Kubernetes and Codex Security. Author: OpenAI Codex deployment engineers · Format: how-to with video · Length: about 8 min. Source: https://developers.openai.com/blog/production-monitoring-with-codex
