## Local models and agents

- Rigtune finds the fastest serving settings for your own GPU — rigtune (formerly PolyServe) tries engines (vLLM, SGLang, llama.cpp), weight precisions, KV-cache types and speculative decoding against your own prompts, caches the winner per machine/model/workload and then serves it through an OpenAI-compatible API. Calibration takes 22-56 minutes per model. The author reports Qwen3.5-35B-A3B on an H200 at 2,018-2,076 tok/s against 912 for stock vLLM, and Gemma 4 12B on an A40 at 996-1,143 against 175, while admitting most of the Qwen gain comes from the model's multi-token-prediction head, the Gemma gain depends on the prompts, and tests covered only 1-8 users on three models and cards. Answers were graded on GSM8K. Built by: Aagam-Bothara · Artefacts: code (MIT) / write-up · Signal: 10 stars, Show HN 2 points (20-21 Nov). Source: https://github.com/Aagam-Bothara/rigtune

- Psudo: a 47 MB, 2-bit ternary coding model with a grammar mask and a pure-Rust engine — a 100.7M-parameter model stored as TQ2_0 weights in a 47 MB GGUF, run by memory-mapped pure-Rust ternary kernels with an INT8 KV cache (no Python, C++ or CUDA). It emits a Polish-prefix intermediate representation (claimed 45-60% fewer tokens) and a pushdown-automaton mask removes invalid tokens before sampling, so decode-time syntax errors are, by the author's claim, zero; a transpiler then lowers verified output to Rust. The README itself says the mask guarantees syntax, not logic, and that the model suits only short single-purpose functions; there are no independent benchmarks. Built by: steveSujo · Artefacts: code (MIT) · Signal: 1 star, Show HN 3 points. Source: https://github.com/steveSujo/psudo

- Kalike, a 435M Kannada-only base model trained nanochat-style — a one-person effort modelled on Karpathy's nanochat training code: d20 has 435M core parameters (897M with lookup tables), pretrained on 4.57B tokens of cleaned Kannada (about 8.9M documents from Sangraha, FineWeb-2, IndicCorp v2 and others) with a 32,768-token tokenizer, and the chat version runs on an Apple Silicon MacBook at about 50 tokens/s. The honest numbers are modest: Belebele Kannada 27.4% against 25% chance, and the chat variants score at chance on multiple-choice benchmarks, which the author attributes to missing multiple-choice training data. Useful as a worked example of what one builder can do for a low-resource language. Built by: Suhas Bhairav · Artefacts: weights (Apache-2.0, data keep own licences) / model card · Signal: Show HN, 2 points (17 Nov). Source: https://huggingface.co/SuhasBhairav/kalike

- Victor's Werkbank benchmarks your whole self-hosted setup, not just the model — 40 fixed tasks sent through any OpenAI-compatible endpoint, each checked automatically, recording time and tokens per solved task. Weights: agentic 30%, coding 20%, security (ignoring injected instructions, no leaks) 15%, retrieval 15%, reliability 10%, math 5%, data analysis 5%. It measures model plus quantisation plus server plus settings plus hardware, and the README declines to offer a leaderboard: scores compare only within one Werkbank version. Results for four setups are in docs/RESULTS.md (not read). Built by: aisyndicate-ch · Artefacts: code (Apache-2.0), docs (CC BY 4.0), tasks · Signal: 6 stars, Show HN 3 points. Source: https://github.com/aisyndicate-ch/victors-werkbank

- Songe trains your local model on its own idle time — it reads your agent conversations (opencode, pi or any OpenAI-compatible tool) for corrections, stated rules, retries and tool errors. "Quick Dream" (minutes) folds stated preferences into the instructions; "Deep Dream" (an hour or more) writes practice scenes, trains a small adapter by on-policy distillation (unchanged model as teacher) and keeps the new version only if it passes checks against your conversations. It runs only when the machine is idle, cool and on healthy battery; MLX on Apple Silicon is the main path. The README publishes no measured improvement. Built by: sous-labs · Artefacts: code (Apache-2.0) · Signal: 19 stars (created 20 Nov). Source: https://github.com/sous-labs/songe

- Unlock: a Claude Code/Codex skill that abliterates a local model on request — drives the open-source Heretic tool: it compares activations for prompts the model answers against ones it refuses, removes the resulting "refusal direction" from selected weight matrices, and writes the edited model to a new folder, leaving the original intact. The author reports one run on Qwen3-4B-Instruct-2507 on a Mac and states the limits himself: the edit was built from one example and one edited answer was factually wrong. Relevant to the access/safety argument because the removal of refusals is now one chat instruction away. Built by: Mark Kashef (Prompt Advisers), on Heretic by Philipp Emanuel Weidmann · Artefacts: code (AGPL-3.0+) · Signal: 20 stars, 12 forks. Source: https://github.com/promptadvisers/unlock

- QDA lets a coding agent design the quantisation recipe — the agent proposes recipes; the system builds each, measures KL divergence from the original model on prompts the agent never sees, checks promising ones on long generations for repetition loops, and keeps the best within a bits-per-weight budget. The shipped checkpoint loads in stock vLLM or llama.cpp. Paper's claims: 0.9-2.2 accuracy points better on average than the strongest public recipe on four reasoning models; on GLM-5.3-Flash at NVFP4 it keeps 98.3% of FP8 accuracy against 96.9% for the best vendor checkpoint; its GPTQ is 2.95-10.69x faster than llm-compressor 0.15 on 2 H100s. The search agent runs without approvals, so the README warns against shared machines. Built by: Xingyang Li, Tianlang Zhao, Song Han, Ligeng Zhu · Artefacts: code (Apache-2.0) / paper · Signal: 14 stars (created 18 Nov). Source: https://github.com/humanfia/qda

- AI Software Factory: GitHub issues to pull requests on your own cluster with open models — a webhook hits a Tekton EventListener (signature and CEL filters), which starts a per-event pod pipeline (fetch skills, plan, agent, verify, publish). The agent step runs OpenCode against vLLM serving Qwen models (Qwen3 Coder, Qwen3.8 Flash) in the same cluster, with no GitHub credentials inside the agent step (a GitHub App issues short-lived tokens in publish). Each model deployment requests 2 GPUs. A concrete reference setup for teams that cannot send code to a hosted API. No licence shown on the page. Built by: piomin (author's identity not confirmed on the page) · Artefacts: code / manifests · Signal: 90 stars, 17 forks. Source: https://github.com/piomin/ai-software-factory

- Terraform module for a private LLM stack on AWS — deploys Ollama, Open WebUI and Caddy (auto-TLS, basic auth) on one EC2 instance with an encrypted EBS volume in about 20 minutes. The interesting part is the cost sheet, an author's estimate for us-east-1 running 24/7: about $40/month for t3.medium with llama3.1:8b, about $570 for g5.xlarge with 70b, about $1,140 for an HA enterprise tier, with suggested client prices of $250/$750/$2,000, so it is aimed at consultants reselling private deployments. Built by: 1solomonwakhungu · Artefacts: code (MIT) · Signal: 2 stars, Show HN 2 points. Source: https://github.com/1solomonwakhungu/terraform-aws-private-llm

## Open-source projects and tools

- Frowse: a token-saving drop-in for the agent-browser CLI — returns 100-300 token page summaries instead of full accessibility trees, collapses repeated items, and resolves natural-language element descriptions with a local CPU model (Folate, covered earlier). Self-reported token counts on three workflows total 19,011 against 74,520 (74.5% fewer), from 91.0% on Hacker News to 54.3% on crates.io; it takes more steps (64 against 41 on the Google Store task), trading many small calls for fewer tokens. Built by: figranium · Artefacts: code (Apache-2.0) · Signal: 2 stars, Show HN 3 points. Source: https://github.com/figranium/frowse

- Stripe World: a stateful fake Stripe for agent evals and RL — 155 operations over 25 tables of Stripe Billing and Payments (pinned to API version 2026-08-26.dahlia), each run getting a private SQLite copy of a frozen fixture with controlled clock, ids and randomness, so the final state (not the transcript) can be graded. Served over OpenEnv, HTTP (with the official Stripe SDKs) and MCP; the README example runs 100 parallel episodes. Not affiliated with Stripe. Built by: Kiln AI, on its Seahaven synthetic-worlds framework · Artefacts: code (MIT) · Signal: 13 stars, Show HN 1 point. Source: https://github.com/Kiln-AI/stripe_world

- WAMT ("Who ate my tokens?") — a single Rust binary serving a local read-only dashboard at 127.0.0.1:7317 over T3 Code's SQLite database, Claude Code transcripts and Codex session files: live threads and subagents with their models, real 5-hour and weekly limits, 30-day history with API-equivalent cost by project, and "wasted tokens" such as expired-cache rebuilds and oversized contexts. Sends nothing off the machine. Small, but it speaks to the bills theme: people are building their own meters for agent subscriptions. Built by: bankerneel · Artefacts: code (MIT) · Signal: 3 stars (created 18 Nov). Source: https://github.com/bankerneel/wamt

- BSWorld: Xiaomi's hardware-free Bluetooth simulation for AI agents and CI — Linux pytest tests drive Zephyr, NuttX, NimBLE, BlueZ, Bumble and Trouble host stacks, each over H4 HCI to its own controller, sharing a simulated BabbleSim radio on a common simulation clock (claimed up to hundreds of times faster than real time), with BTSnoop captures for Wireshark. The point is that a coding agent can iterate on Bluetooth code without a bench of hardware. Built by: XiaoMi organisation (individuals not named) · Artefacts: code (Apache-2.0) · Signal: 19 stars, Show HN 5 points. Source: https://github.com/XiaoMi/bsworld

- CheeseDB: agent memory where deleting a source deletes what it taught — an embedded Go database (standard library only, append-only hash-chained log, MCP server, optional embeddings through any OpenAI-compatible server) in which each memory records the sources it was learned from. Recalling a source removes derived memories: Fair keeps those with another independent source, Strict removes everything that touched it, Erase also removes the text from disk. Preview, not for production; the README says Claude wrote much of the code and the author reviewed every change. Built by: govinargo-labs · Artefacts: code (Apache-2.0) · Signal: 14 stars, 5 forks, Show HN 7 points. Source: https://github.com/govinargo-labs/cheesedb

- WineDroid: Android APKs without Android, in Rust — an experimental compatibility layer, "Wine for Android": it executes DEX bytecode, reimplements framework behaviour and renders with Skia; desktop builds have a Cranelift JIT, the roughly 12 MB WebAssembly build uses an interpreter and cannot load native .so libraries. Unimplemented methods print FIXME and return void/zero/false/null. Its app database lists six working apps; the author says early development and intermittent work. It reached the Hacker News front page (108 points) on 20 Nov; the repository's creation date is not shown, and the page does not say whether AI tools were used. Built by: sohzm · Artefacts: code (GPLv3) / browser demo · Signal: 77 stars, HN 108 points. Source: https://github.com/sohzm/winedroid

Runs open-weight models locally (the post recommends Qwen 3.8 27B) and imports Pi, OpenCode and Codex configs. ## Agents and automation

- OpenComputer: an open-source alternative to Devin that lives in Slack — mention @Computer in a thread and an agent (Claude Code, Codex or OpenCode) works on its own VM and opens a PR. A gateway starts one session per thread in rootless Podman on a VM that only dials out to Cloudflare Workers and Durable Objects; state goes to local disk and then a git-backed store. The makers claim PRs 3.3x faster than Devin (56 s against 185 s with CI green) and first push in 24 s against a 62 s average of four cloud agents, and that one always-on 4 vCPU VM beats per-session E2B sandboxes beyond about 640 session-hours a month. Their own numbers; two Cognition employees replied in the thread disputing the characterisation of Devin's pricing and default model. Self-hosting currently means your own cloud account plus Cloudflare, not a home server. Built by: diggerhq · Artefacts: code (Apache-2.0) / hosted trial · Signal: 757 stars, HN 72 points, 22 comments. Source: https://github.com/diggerhq/opencomputer

- openRocode drives robots the way agents use computers — the model sees camera images, clicks where the gripper should go, nudges in camera-relative directions, or writes a short Python program; depth, calibration and inverse kinematics stay in the harness, so the model never touches world coordinates. A roughly 700-line agent loop calls model APIs directly so every message can be guarded, interrupted and recorded; tasks are TOML files with hidden success checks; runs in MuJoCo without a GPU. Smoke test: 58 of 60 episodes succeeded across four tasks with Claude, an OpenAI-compatible model and others, and the author says the tasks are too easy to rank models. Alpha. Built by: wrencanfly · Artefacts: code (Apache-2.0) / trace dashboard · Signal: 10 stars (created 18 Nov). Source: https://github.com/wrencanfly/openRocode

- dsh-projects: a project board for DeepSeek Harness — one goal, a shared memory file and a task board; a coordinator session plans and dispatches tasks to 1-8 worker subagents, each with its own context and optional git worktree, and a human accepts output with a "Resolve" toggle (Manual or Auto autonomy). Workers are in-process and stop when the plugin is disabled; no cloud execution or scheduling yet. Shows the harness-plugin ecosystem forming around a non-US model. Built by: fatwang2 · Artefacts: code (MIT), npm bundle · Signal: 11 stars, 67 commits. Source: https://github.com/fatwang2/dsh-projects

- Treasure Map: a firmware map for a coding agent, served over MCP — headless Ghidra 11.4.3 decompiles unpacked firmware, flags command-execution, memory-copy, format-string and file-path call sites and annotates each with layered YES/NO/UNKNOWN facts (data source, attacker control, reachability, filtering); no scores and no verdicts, the model supplies judgment. `tmap diff` adds a BinDiff patch comparison. Case study: DeepSeek-V4.1-Flash reviewed the patch for CVE-2021-26614 in an ipTIME C200 camera and judged all 144 must-read items for an author-reported $0.5-1, concluding the backdoor was unlinked not removed, the bigger buffer still takes a client-chosen length, and validation was added only in the browser. Developer preview. Built by: JoeyZzZzZz · Artefacts: code (Apache-2.0) / case study · Signal: 14 stars, Show HN 3 points. Source: https://github.com/JoeyZzZzZz/treasure-map

## Experiments, demos and write-ups

- Vibe-coding an FPGA to run a ternary LLM at 213 tok/s — Ankit Gupta had coding agents (Codex for AWS set-up, a Conductor cloud agent switching between two Claude models for days) build an inference design for a ternary-weight model on an AWS F2 FPGA instance ($1.98/h, 16 GB HBM), mostly C++ and some Verilog he says he had never written, steered by about 166 encouraging prompts. Throughput went from 6.43 tok/s (first bit-exact full-model image) to 213.13 tok/s (33x) at 225/425 MHz after a soak test found faults at 231.25 MHz; 24 of 24 benchmark turns matched the CPU reference, against a CPU twin at 129.5 tok/s for $1.95/h and a community CUDA port at 166.3 tok/s on a T4 that was not bit-exact. The cost line is the story: about $10,000 of Claude and OpenAI tokens and roughly 3M lines of experiment history. No repository link or licence in the post. Built by: Ankit Gupta · Artefacts: write-up · Signal: HN 118 points, 34 comments. Source: https://ankitg.me/blog/vibecoding-inference-chip/

- Claude-written FLAC, MP3 and DST decoders that beat FFmpeg 1.6-3.5x — the decoders from the Orpheic music player, C++17 without dependencies, written by Claude under the author's rules. FLAC and DST output matches FFmpeg byte for byte (FLAC also matches libFLAC); MP3 has no bit-exact reference, the fast path differing by at most 0.42 millionths of full scale. Speed (decoder only, one thread): FLAC 2.37x on an i9-14900K, 3.45x on an M4, 1.58x on a Raspberry Pi 5; MP3 fast path 2.25x/2.76x/2.27x; the MP3 exact path is only 0.14-0.27x. DST figures use excerpts that cannot be shared. Separate AI reviewers looked for copied code and one MP3 section that resembled another decoder was rewritten. Built by: Georgios Kakavelakis · Artefacts: code (MIT) / check tools · Signal: 1 star, Show HN 2 points. Source: https://github.com/orpheic/orpheic-decoders

- indexed_bzip2 2.0, "the first release using AI assistance" — release notes of 18 Nov: parallel compression in the CLI, SIMD block-magic search, faster symbol decoding and CRC, NEON for ARM, 2-8x faster than 1.7.0 depending on data and threads (4.2x on constant data for the CRC; 1.32x on Silesia single-core). Honest limits: on low-ratio data such as FASTQ it is roughly at GNU gzip parity and well behind igzip. Notes do not say which parts the AI covered. Built by: mxmlnkn · Artefacts: code release (licence not stated on the page) · Signal: Show HN 2 points. Source: https://github.com/mxmlnkn/librapidarchive/releases/tag/v2.0.0
