## Safety and security

- Claude Code's "Yes, and don't ask again" choice can save a typed password or key in plain text in a public project file: 1,122 public copies hold at least one secret — The Hacker News (7 November) on a write-up by the security firm Apiiro (dated 6 November per the article; the Apiiro page itself returned a Cloudflare block, so details come from The Hacker News; the Hacker News thread of 7 November, 20:45 UTC, has 205 points). When a user approves a command and picks "don't ask again", Claude Code stores an allow rule in .claude/settings.local.json; if the rule is the exact command, the secret in it is stored too. Apiiro found 104,185 copies of the file in 103,617 public repositories; 1,122 copies (about 1.1%) held 1,379 distinct secrets, including 379 database passwords, 43 SSH logins, 42 GitHub/GitLab/npm tokens and 23 AWS keys; 63 organisations are among the owners. In 539 of 1,105 traced repositories a commit with Claude as co-author changed the file. Claude Code adds the file to the user's global git excludes, but never to the project's .gitignore, so the protection does not travel with the repository or cover files already committed. Apiiro did not test whether the secrets still work; one notified company confirmed its key was live. Advice: rotate every secret the file ever held, then clean up. This is a vendor-research finding; the counts are Apiiro's. Source: https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html
