## Local models and agents

- Streaming a 125B MoE model on a PS5 running Linux — A from-scratch C++20/GLSL inference engine (no llama.cpp, no ROCm) runs the 125B-parameter mixture-of-experts Qwen3.8-Flash-Next on a PS5 with 16 GB unified memory. Experts stream from an M.2 NVMe SSD into a ~12 GiB pool the GPU reads through Vulkan compute. The README reports 49-57 tok/s decode and 320-340 prefill, context to 262k tokens (13.1 tok/s at 194k), and a 120k-token conversation restoring in ~1 s versus 418 s to re-prefill; quality against a ~4.5-bit reference is top-1 agreement 0.932 (EXL3 3.18 bpw experts). It exposes OpenAI- and Anthropic-compatible APIs. The console must already boot Linux and the repo ships no jailbreak. Numbers are the builder's own; the project began in October as a course project. Built by: LaRazaDelSol · Artefacts: code (MIT; kernel modules GPL-2.0) · Signal: 14 stars. Source: https://github.com/LaRazaDelSol/AIEngineOnSmallUniMem

- Sync-Strata: one-click local 125B MoE with re-quantised weights — A Windows/Linux app that runs Qwen3.8-Flash-Next (125B MoE) on a home PC, a fork of the Strata engine by Niko1221. It adds three re-quantised variants picked by RAM (XS for 24 GB or less, S for 32 GB, M for 48 GB or more), "tail skip" (fewer experts per token) and KV-cache compression. On the author's Ryzen 7 7800X3D, 32 GB RAM, RTX 3080 12 GB it reports 144 tok/s decode for Sync-S against 43 for upstream Gyro-M. Experimental; only RTX 30/40 checked, Linux benchmarks not yet measured; model under the Qwen Community License. Built by: hiruhiru2005 · Artefacts: code (MIT), quantised models · Signal: 32 stars. Source: https://github.com/hiruhiru2005/sync-strata

- strata-ddkRDNA3: measured tuning of the same model on an RX 7900 XTX — An RDNA3 fork of Strata with launch flags, a quantisation study and notes on upstream bugs, running Qwen3.8-Flash-Next at UD-IQ4_XS (87 GB) on a 24 GB card under Windows HIP. The interesting part is the honesty: raising the conversation cache from 8 to 16 GiB and slots from 4 to 8 took evictions from 142 to 0 and cold prefill from 25-40 s to 1-3 s, while the two decode switches gave +1.5% (88.2 to 89.6 tok/s), which the author reports as not statistically significant (Welch t = 1.43). Single machine, 3-5% run variance, 44 non-default environment variables. Built by: ddk103 · Artefacts: code (MIT), write-up in README · Signal: 5 stars. Source: https://github.com/ddk103/strata-ddkRDNA3

- NØX-Local: a terminal coding agent for 8 GB GPUs — A Go agent with its own TUI on top of llama.cpp (Vulkan), designed for small models: ten built-in tools, plain-text tool-call recovery, a loop guard, plan mode, Git-based undo, opt-in MCP and skills; only WebSearch/WebFetch touch the network. Measured on an RX 6500 XT 8 GB: Qwen3.5 4B at 32 tok/s with 64K context, 9B at 9 tok/s, a 27B at 3 tok/s through `--fit`. The author recommends the 4B as default; release candidate 1.0.0-rc1. Built by: Jan Raszka · Artefacts: code (MIT) · Signal: 5 stars. Source: https://github.com/Johnny008-creator/nox-local

- milo-pointer: a 149M on-device first tier for phone agents — A ModernBERT-base fine-tuned on AndroidControl handles the GUI steps it is confident about (~70%) on the phone and defers the rest to Claude Opus 5.5 or Sonnet 5.5; training takes ~6.4 h on one T4. On 1,000 held-out single steps the author reports 892/890 correct routed to Opus against 882/879 for Opus alone, at $2.82 versus $9.54 per 1k steps; a 650-step confirmation gave +2.8 points (p = 0.003). Stated limits: ~3.4 s per step on a Pixel 6a CPU, and a comparable cascade lost on live AndroidWorld tasks. A follow-up 1.5B Qwen2.5 LoRA planner reaches 53.0% against 90.2% with human instructions. Offline step accuracy is the builder's own measurement. Built by: Chaitanya Talapalli · Artefacts: code and weights (Apache-2.0; weights on Hugging Face) · Signal: Show HN, 1 point. Source: https://github.com/chayworks/milo-pointer

- smoothstone: small local models that make 3D-printable parts without writing geometry — A skill plus CLI (`stone`) in which a tiny model (LFM3-1.7B on CPU) only picks one of 16 tested OpenSCAD recipes and fills in sizes; the tool builds the part with OpenSCAD/Manifold and checks the STL (watertight, wall thickness, overhang, first-layer contact), keeping every step on disk so the model survives context loss. Photos go through a chain of LFM3-VL-2B, FLUX.2 klein 4B and Hunyuan3D-2mini. The author reports the right part with right sizes in 39 of 40 blind runs (38 of 40 with memory wiped mid-job), against 0 of 15 when the same model wrote OpenSCAD directly; logs and eval sets are in the repo, not independently verified. Built by: baney75 · Artefacts: code (MIT; one model under Tencent's community licence) · Signal: 75 stars. Source: https://github.com/baney75/smoothstone

- inside-llm: watch what a GGUF model does token by token — A browser UI over a C++17 engine linking llama.cpp that shows per-step probabilities, entropy, what each sampler removed, and (with two models sharing a tokenizer) where two quantisations diverge, with an optional logit lens (~2 GB RAM per model, ~30 ms per step) and replayable recorded sessions that need no GPU. Svelte 5 frontend, binary WebSocket frames, CUDA or Vulkan. Useful for seeing what a quantisation actually changes. Built by: Manuel García · Artefacts: code (MIT), v1.0.0 · Signal: 105 stars. Source: https://github.com/manuelgscom/inside-llm

- Replica: 100 ms copy-on-write workspaces for agents on macOS — A CLI that builds a reusable base once (clone plus installed dependencies) and then creates each agent workspace with one `clonefile(2)` call on APFS, so blocks are shared until written. On an M1 Max with a 1,739-file npm project under load it reports ~100 ms against ~958 ms for `cp -c -R` and ~3.96 s for clone plus setup; ~1.4 MB metadata per clone, TTL/LRU/byte caps for cleanup. Limits stated: same APFS volume, absolute-path build output breaks in clones, very large trees unmeasured. Built by: gabrielvfonseca · Artefacts: code (Apache-2.0) · Signal: 1 star, Show HN 3 points. Source: https://github.com/gabrielvfonseca/replica

## Open-source projects and tools

- rust-anything: rewrite an app in Rust one piece at a time, checked against recordings — Records the original program's behaviour on generated edge cases, generates a Rust crate plus a wrapper keeping the old API, and replays every recorded case through `diff` and a `gate` before a unit counts as done; the developer or a coding agent writes the Rust, the tool supplies recording, bridging and the gate. Supports Node/TypeScript, Python, C, Go, Ruby, Java (PHP and C# preview). It claims 38,251 replayed cases with 0 mismatches and up to 20x speedups (x18n search 10 ms to 0.5 ms), but its own README notes calling Rust per small function is often slower than a JIT. Fast-moving: created 16 November. Built by: erKam Yaman · Artefacts: code (MIT) · Signal: ~3.5k stars, 283 forks. Source: https://github.com/erkamyaman/rust-anything

- Pitot: observability that agents operate, in one binary — A Go single-binary OpenTelemetry backend: OTLP in, Parquet storage, DuckDB queries, SQLite control state, React UI, and an on-by-default MCP endpoint (OAuth, Streamable HTTP) exposing the same typed query tools as its built-in agent. Pre-release alpha with no migration paths. Built by: LabStack LLC · Artefacts: code (Apache-2.0) · Signal: 139 stars, Show HN 3 points. Source: https://github.com/labstack/pitot

- Nexus: a local MCP server for web AI chats — Exposes local files, terminals, Git and Windows computer-use tools to web AI assistants through a Fastify MCP server (port 18080) and a Rust local runner over WebSocket JSON-RPC; per-project read/write and execution modes, a command risk engine, path sandboxing and an action ledger. The README claims 332 tools in 24 areas and warns tool output sent to a web chat leaves the machine. Built by: ysunyang4 · Artefacts: code (AGPL-3.0) · Signal: 408 stars, 13 commits. Source: https://github.com/ysunyang4/Nexus

- Signet: governance registry for agents and skills — Tracks what an agent or skill means, its release state and evidence, with SHACL and ontology validation, advisory LLM analysis, human review, signed publication envelopes (JCS/RDFC canonicalisation) and an append-only Merkle log linked to a Tessera transparency log; exposes MCP and API. A supply-chain take on agent skills. Built by: Derek C. and Pablo Ferrari (account therandomsecurityguy) · Artefacts: code (BSD-3-Clause) · Signal: 141 stars, 281 commits. Source: https://github.com/therandomsecurityguy/signet

- Dez: a plaintext AI multimedia studio — A Tauri v2 / Rust / Vue 3 desktop app for talking to models inside an editable plaintext document (inspired by Zed text threads), with Seatbelt (macOS) and landlock (Linux) sandboxing. Built by: taoeffect · Artefacts: code (AGPL-3.0) · Signal: 11 stars, Show HN 5 points. Source: https://github.com/taoeffect/dez

- Anima Brain: local persistent memory for AI companions — Python SDK on SQLite/FTS5 with MCP tools; each reply goes through prepare-context, generate, validate-and-commit-memory. Bring your own model; MCP hosts must call the memory tools explicitly. Alpha 0.6.0. Built by: Jun Yu Chen and kayllla · Artefacts: code (MIT) · Signal: 76 stars. ## Experiments, demos and write-ups

- LLM-assisted reverse engineering, a hobbyist's workflow — The author reports using DeepSeek v4.1 Flash in the DeepSeek harness (occasionally Codex), Ghidra through an MCP bridge, Python probes and Rust for the actual hacks, to map camera protocols, patch synthesizer firmware, fix an old printer driver and write custom firmware for an e-reader. Method: have the agent write findings to Markdown notes to survive context compaction, then run an explicit loop of hypothesis, experiment, record. Self-reported results. Built by: ioma8 · Artefacts: write-up · Signal: HN front page, 83 points. Source: https://www.slowchronicle.com/posts/llm-assisted-reverse-engineering

- Broken Arm Bench: a meta-RL agent keeps drawing with a damaged arm — A demo where a robot arm that has never seen its damage tries a few moves, remembers what they did and adapts, with no retraining. Trained over 1,000 episodes with motor strength 0.5x-1.5x; beyond that range it inks ~75-95% of the target word against ~35-75% for an LSTM agent trained for 4,000 episodes, and it converged on something like a hand-written self-calibrating controller (which does better on plain strength changes, while the meta-RL agent does better with drag and combined damage). MAML never learned the task. Author's own benchmark. Built by: Chris Martinez · Artefacts: demo, code (repo RandMan444/meta-rl-draw) · Signal: Show HN 1 point. Source: https://randman444.github.io/meta-rl-draw/web/

- orb-audio: a 15M-parameter caption-to-sound-effects engine for agents — A small planner (6 layers, d=256, byte-level tokenizer, constrained decoding) turns a caption into a typed JSON score that a NumPy DSP renderer plays at 48 kHz stereo, so timing is exact and edits are numeric. The planner scores 500/500 on its own held-out grammar captions but is fully correct on only 58.4% of free-text prompts on the author's set (70% on a blind set); the optional detail model misses its own gate (+0.84% against a 10% target) and is non-commercial. Parameter counts are inconsistent in the README (15M header, 14.16M total). Built by: Marcos Maceo (AI-assisted with Claude) · Artefacts: code (Apache-2.0) · Signal: 7 stars. Source: https://github.com/stdevMac/orb-audio

- springrep: a pure-Rust B-rep CAD kernel for robotics — Booleans, fillets, sweeps and STEP on exact geometry, no dependencies, no unsafe code, compiles to WebAssembly; the Show HN title cites 3,487 tests (not confirmed on the page). The page includes instructions addressed to AI agents, which were not followed. Built by: Springcraft · Artefacts: code (MIT), demo · Signal: Show HN 21 points. Source: https://springcraft-ai.github.io/springrep/
