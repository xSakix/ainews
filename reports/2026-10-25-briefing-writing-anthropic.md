## Deep dives and technical write-ups

How Cerebras deploys trillion-parameter frontier models on wafer-scale chips — Cerebras engineer Sarah Chieng answers the question the company says it gets most often: how a model whose weights need terabytes runs on wafers with only 44 GB of on-chip memory each. The post works the arithmetic out loud using Kimi K3 (~3T parameters, 69 linear-attention and 24 dense layers) at 4-bit weights and an 8-bit KV cache, showing how the model is split layer-by-layer across many WSE-3T wafers to serve 1,000-2,000+ tokens/s, and how concurrency is handled. Useful for the reader following the economics of inference hardware off the Nvidia path, with the per-layer memory maths laid out to inspect rather than asserted. The benchmark figures it cites for Kimi K3 (88.3% Terminal-Bench 2.1, 91.2% BrowseComp) are the company's framing, not an independent test. AnyLanguageModel 1.0: one year of local models on Apple platforms — Mattt (Hugging Face) marks the 1.0 release of a Swift library that is a drop-in replacement for Apple's Foundation Models framework: you change `import FoundationModels` to `import AnyLanguageModel` and the same session code then runs against the system model, local open weights via llama.cpp, MLX and Core ML, or hosted providers, behind one API. The retrospective describes the features added over the year — tool calling and guided generation (including nested `@Generable` types) across every provider, image attachments using the Foundation Models 27 syntax, and support on OS 27 for anything conforming to the `LanguageModel` protocol including Apple's Core AI models — alongside the related swift-huggingface and swift-xet 1.0 releases. Worth reading for app developers weighing local versus hosted inference on Apple hardware; the claims are the maintainer's own, with the code on GitHub to check. Author: Mattt, Hugging Face (library maintainer) · Format: deep dive / release write-up · Length: about 8 min read. Source: https://huggingface.co/blog/anylanguagemodel-1-0

## Essays and arguments

"We should be more ambitious with the software we build" (Dan Luu) — Luu argues that fast, high-quality coding models change the calculus of what software is worth building: optimizations and tools that were never worth a human's time become feasible, so individuals can now tackle work that used to need a team or simply went undone. He grounds the claim in his own weekend projects prompted by the prospect of SOTA models running 10-100x faster (e.g. OpenAI using Cerebras) — a tweakable regex engine he says beats general-purpose libraries on chosen workloads, a ripgrep fork built on it, and a Rust change that speeds his cold builds — and contrasts this with the flood of low-quality "vibe-slopped" AI projects that make good work hard to trust. This is an opinion piece; the performance wins are his own anecdotes on his own workloads, not independently measured, and he says so. Useful as a practitioner's counter-narrative to "AI makes programmers obsolete": the argument is that it raises the ceiling on ambition instead. Author: Dan Luu, software engineer and blogger · Format: essay · Length: about 20 min read. Source: https://danluu.com/ambitious/

## Prompting and context techniques

Force an outline pass before any deck tool generates slides (r/PromptEngineering) — A poster reports that the biggest jump in AI-generated deck quality came from refusing to let a slide tool build anything until the structure is locked in plain text, and shares the reusable prompt: cast the model as a "presentation strategist", have it ask up to five questions (audience, the one decision you want, the single argument per section, what to cut), wait for answers, then output only a slide-by-slide outline — one idea per slide, headline plus supporting point, no design. The stated reason it works: it moves the thinking to a stage where editing is cheap. The author also reports a concrete failure mode — handing Gamma 5 an already-locked outline made it over-restructure and merge sections, so the order had to be pinned back. Evidence is the author's own experience, not a controlled test; the value is a specific, copyable prompt and a named caveat. Author: r/PromptEngineering user (self-reported practitioner experience) · Format: community technique · Length: 3 min read.
