## Local models and agents

- llm.asm — Qwen3-0.6B inference, a bootable OS and a Mini-GPT trainer in hand-written x86-64 assembly. Three projects in one repo (17,252 lines of NASM, no C, no libc): a static ELF that runs Qwen3-0.6B with its own BPE tokenizer, a bare-metal image that boots straight into the model, and an FP32 trainer with AdamW and a backward pass. Binaries are 14.7 KB (inference), 24.3 KB (OS) and 32.9 KB (trainer), although the README headline rounds these to 12/22/32 KB. The author reports 126.8 tok/s decode at 40 threads on an AMD EPYC 7642 and 18-36% faster decode than llama.cpp CPU Q8_0, with cosine 0.99965 against PyTorch. Limits: the comparison is not like for like (llama.cpp batches prefill, llm.asm does not), it needs AVX2/FMA/F16C, weights are exported with a Python script, and the trainer sample is a 400-step TinyShakespeare run. Built by: alesha-pro (individual) · Artefacts: code (MIT) · Signal: about 365 GitHub stars within a day of creation (repo created 25 Nov). Source: https://github.com/alesha-pro/llm.asm

- FLYX — a CUDA-first local inference engine in a ~50 MB binary. Runs GGUF models behind OpenAI- and Anthropic-compatible APIs with a web dashboard and one-click launch of Claude Code or Codex CLI (Windows only). The author reports 350.2 tok/s on an RTX 5090 (NVFP4) at 1K context falling to 164.5 at 256K, and 193.6 tok/s on an RTX 4090 (UD-Q4_K_XL) falling to 122.7 at 256K, measured with greedy 512-token code generation and not independently checked. Limits: dense text models only (no MoE or vision), one GPU per process, NVIDIA driver 580 or newer, and building needs CUDA 13. Built by: enwove · Artefacts: code (Apache-2.0) · Signal: 41 stars (repo created 23 Nov). Source: https://github.com/enwove/flyx

- Rustling — a Rust and Metal inference engine for Apple silicon that runs only the Inkling 2 Mini family. It serves an OpenAI-compatible API for coding agents (Codex, aider, opencode) with prompt caching that survives restarts. On an M1 Max 64 GB against llama.cpp the builder reports 24 vs 21 tok/s on short chats, 102 s vs 182 s for a 15,000-token prompt, but slower (21 s vs 19 s) on a 2,400-token prompt; the 4-bit conversion matches the published checkpoint's next-token choice 84-94% of the time. Limits: Apple silicon only, text only, one request at a time, and a 16.6 GB model that strains 32 GB machines. Built by: onatm (individual) · Artefacts: code (Apache-2.0 or MIT) · Signal: 10 HN points, 4 stars. Source: https://github.com/onatm/rustling

- openfal — a fal.ai-compatible API for local image and video generation. One CLI (detect, autosetup, serve) exposes fal-style routes, a queue with SSE status and a fal_client-style Python SDK in front of Qwen-Image-2.1, Wan 2.2 and MiniMax H3, so apps written for the hosted API can be pointed at your own GPU. ## Open-source projects and tools

- Ephyra — property-based testing for coding agents, from Datadog Systems Research. A Rust library where you write a property as a bool-returning test; Ephyra writes an input generator, measures coverage and rewrites the generator to reach new code, contrasted with fuzzers that mutate inputs. The README claims 70+ bugs in SQLite, 20 in PostgreSQL, 25 in Lean and several in FoundationDB and TigerBeetle, with case studies in the repo (self-reported, not independently checked). Limits: version 0.0.1, README says almost all code is experimental, docs are written for agents, and some case studies need external checkouts. Built by: Datadog Systems Research (datadog-labs) · Artefacts: code (MIT) · Signal: 305 stars. Source: https://github.com/datadog-labs/ephyra
HN: https://news.ycombinator.com/item?id=50643333

- SAP Data MCP — 412 read-only MCP tools for SAP S/4HANA. Three Python servers (RFC/BAPI, OData for private cloud, released APIs for public cloud) let Claude Desktop, Claude Code or Cursor query inventory, sales, finance and basis monitoring. The interesting part is the safety design: the RFC server only calls a whitelist of 98 standard read functions, HTTP servers send GET only, secrets are redacted in logs, every call goes to a daily JSONL audit file, and results carry a status (ok, not_found, partial, error) so an empty list is not read as a zero balance. Limits: strictly read-only, young (4 commits, 0 forks), RFC path needs PyRFC and the SAP NW RFC SDK, demo data is fictional, not affiliated with SAP. Built by: w1ccc · Artefacts: code (MIT) · Signal: about 160 stars (repo created 20 Nov). Source: https://github.com/w1ccc/sap-data-mcp

- Modelpin — regression tests for switching LLM models. A CLI and GitHub Action: you describe your app's requests as JSON scenarios, `baseline` runs them several times on the current model, `check --to <model>` replays them on the candidate and compares tool-call sequences, refusals and meaning (judged by another LLM). A regression must be statistically significant, large enough to matter and reproduce on a fresh run; a `watch` command checks configured models against a bundled deprecation registry. Limits: only covers scenarios you write, the judge is a model, it can miss a shift that happens in one run of five by design, and the author reports four same-model false alarms so far. Built by: samarthputhraya · Artefacts: code (Apache-2.0, open-core), PyPI v0.5.6 · Signal: 2 stars, 1 HN point. Source: https://github.com/samarthputhraya/Modelpin
HN: https://news.ycombinator.com/item?id=50644468

- Warmy — a Mac menu-bar proxy that keeps Claude Code's prompt cache warm. It points Claude Code at a local proxy and sends a warm-up request before a chat's cache expires, betting on the cache read price (0.05x) versus a cold rewrite (2x input price); a model of your usage picks which chats to keep warm. Its example: a chat with a 3-hour break costs 587k tokens cold vs 59k warm; headline "save up to 15% of your usage". Limits: savings depend on your habits and on Anthropic not changing cache rules, Mac and Claude Code only, the proxy is MIT on GitHub but the app is paid ($1.99 launch price, then $19.99) and closed, and the numbers are the vendor's examples. Built by: unnamed individual or small team · Artefacts: open proxy (MIT), paid app · Signal: 1 HN point. Source: https://warmy.dev

## Agents and automation

- ai-sdlc-factory — label a ticket, get a reviewed pull request. Role agents (analysis, implementation, code/security/UX review) run in disposable containers whose only network route is an allowlisting proxy, orchestrated by Temporal on .NET 10 with Docker Compose. Agents return one validated JSON verdict and code, not the model, decides the next step; bug labels require a fix proven by a test that fails before and passes after; the factory never merges. Tested route is a ChatGPT Plus/Pro account through OpenCode; Forgejo and GitHub both run live. Limits: no benchmarks or usage numbers, "young software", agents sit next to a Docker daemon (read the security notes before untrusted repos), about 30 minutes to set up. Built by: ai-sdlc-factory · Artefacts: code (MIT) · Signal: 26 stars (repo created 22 Nov). Source: https://github.com/ai-sdlc-factory/ai-sdlc-factory

- git-ontology-agent — talk to an agent mid-task, with every request a git branch. Each new message is classified (supplement, correction, independent, cancel, progress) by a decision model; low confidence (below 0.8) triggers a clarifying question; a claim-level three-way merge reconciles branches. Pure Python standard library, commits via git plumbing without checkouts, supports OpenAI, Anthropic, Gemini, xAI and OpenRouter, Ink terminal UI. Limits: no cross-session memory, no multi-agent, one unresolved merge case depends on a judgment threshold, v0.1.0 and no evaluation. Built by: gogoymh · Artefacts: code (MIT) · Signal: 34 stars (repo created 21 Nov). Source: https://github.com/gogoymh/git-ontology-agent

- Filament — an agent harness that shares one memory across models and agents. Desktop app (Electron, plain ES modules with JSDoc, no build step) with its own coding agent plus Claude Code, Codex and Cursor running inside it, a local API on one port accepting Anthropic- or OpenAI-format clients, parallel helpers in git worktrees, and local encrypted memory (about 500 MB engine). The maker's own use shows roughly 2x speed, 40% fewer tokens and 98.87% of input tokens read from cache; no published benchmark. Limits: early (30 stars), official builds send anonymous usage counts by default. Built by: invertibleMatrix · Artefacts: code (Apache-2.0) · Signal: 30 stars (repo created 21 Nov). Source: https://github.com/invertibleMatrix/filament

Rust workspace plus npm CLI. Limits: 3 stars, security model not reviewed here, Linux (systemd) or macOS 13.5+. Built by: anthod0 · Artefacts: code (Apache-2.0) · Signal: 2 HN points. Source: https://github.com/anthod0/pontia

- drumsd — fork whole Linux desktops from a checkpoint for computer-use agent training. A Rust daemon that runs many isolated Ubuntu desktops on one host, each restored copy-on-write from a CRIU checkpoint rather than booted, with validity gates and a reward audit per episode; uses cgroups, namespaces and eBPF. - 🚨 Much shorter Lean proof of the Riemann Hypothesis, made with Claude — repo posted to Hacker News. A repository with Lean 4 / Mathlib formalisations of the Riemann Hypothesis and the Generalized RH for Dirichlet L-functions, in two editions: about 300,000 readable lines and a golfed 76,000-line version of the same five theorems; copyright Anthropic, PBC, based on Levent Alpöge's work developed with Claude. It uses only the standard axioms (propext, Classical.choice, Quot.sound) and takes 1-2 hours on 12 cores and 24 GB to build. HN commenters (306 points, 138 comments) cite a drop from roughly 17M lines and say the core is about 35k lines, but also that no mathematician has read it, there is no accompanying paper, and the repo is on a personal account. The repo's own claim rests on machine checking only; the repo says it is unmaintained and takes no contributions. Built by: lsernau with Anthropic colleagues and Claude · Artefacts: code (Apache-2.0) · Signal: 306 HN points, about 330 stars. Source: https://github.com/lsernau/grh-lean

- Jev is probably Qwen3.5-35B-A3B — fingerprinting a closed model through latency. Modaic's post (24 Nov, Tyrin-Ian Todd and Farouk Adeleke) tries to identify the backbone behind TypeSafe's Jev API. Over 9,976 requests, median latency rose from 77 to 155 ms with a narrow p50-p99 spread (read as sparse MoE); 22 self-identification prompts split roughly 50/50 on Qwen but Jev rejected DeepSeek (95-98%) and Gemma (86-90%); prefill throughput above 90K tok/s tracked a Qwen3.5-35B-A3B model most closely, where a dense 27B plateaued near 35K; controls with known Gemma- and Qwen-based models showed the method can recover a tokenizer. Limits: a performance fingerprint, not proof; Jev's hardware and replicas are undisclosed; Qwen3.6-35B-A3B shares the architecture; the post has a small inconsistency (9,976 vs 9,984). Built by: Modaic researchers · Artefacts: write-up · Signal: 236 HN points. Source: https://modaic.dev/blog/latency-doesnt-lie

- Predicting LoRA size for any dataset. Engram (24 Nov) estimates the rank a LoRA needs by measuring how many bits the dataset takes under the base model: synthetic N-bit datasets built by running arithmetic coding backwards through the model give a capacity curve, and real datasets are scored with 2M-token context via YaRN. Reported: predicted rank within 5% on their runs (an internal-email example predicted 3.45, measured 4.26), models forget about as many bits as they learn, and stacked adapters reach about 3.3 bits per parameter against a theoretical 1.3. Limits: all experiments use Qwen3.5-0.8B with alpha 256, LoRA only, capacity at infinite training is extrapolated, no code or model released, and the company sells per-user models. Built by: Engram (company, no named authors) · Artefacts: write-up with interactive figures · Signal: 114 HN points. Source: https://engram.com/blog/lora-size
