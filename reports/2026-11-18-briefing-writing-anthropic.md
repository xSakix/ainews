- RUNTA and Baseten: FrontierHarness Eval v1.1 — which agent harness is best depends on the model — The authors ran 22 harness configurations (18 harnesses) against 5 open-weight models (GLM-5.3, GLM-5.3 Flash, DeepSeek-V4.1-Flash-1017, Muse Spark Open, Kimi-K3) on 62 terminal tasks with 4 attempts each: 27,280 agent runs and 83B tokens, 76x the size of v1.0. - TIS-100 Bench: 16 LLMs set new frontier points in a decade-old programming puzzle game — Wincon gave 16 models the game and its manual, withheld the community leaderboard (frozen on 15 October 2026), and let each model make one scored attempt per puzzle across 55 puzzles, with 10 to 45 minutes each. A "new frontier point" counts only if no community solution ties or beats it on cycles, nodes and instructions, and the program passes 100,000 tests on an independent simulator. Opus 5.5 and GPT-6 Astra both solved all 55 and found new points on 11 puzzles. Opus 5.5 found more points (72 vs 32), while Astra has a slightly higher "record proximity" (78.0 vs 77.2, gap within bootstrap noise). Fable 5.1 solved fewer puzzles (52) but found new points on 5, so solving and optimizing are different skills. The models made 133 new points in total, with 3 outright cycle records. In one tournament puzzle Opus 5.5 beat the best community program by 29%. Players then improved on most of the models' programs within days. - vLLM, Meta and Google: reinforcement learning for a 0.6B model on TPU v7 goes from about 100 minutes to 56 seconds per cycle — For a small dense policy the bottleneck moves from FLOPs to coordination: decode scheduling, synchronization, attention geometry and KV-cache lifecycle. The team co-designed across vLLM, Tunix, MaxText and Pallas on a 64-chip TPU v7 slice and upstreamed the changes. They report a 107x speedup of a full rollout-to-update cycle with the full 8,192-token response budget (about 183K tokens/s). - Simon Willison and Prime Radiant: external sandboxes for coding agents — Willison describes a pattern in which the agent stays outside and only the code it executes runs in a dedicated sandbox. Three server implementations share one localhost API: v86 (Alpine Linux in WebAssembly), Apple Containers, and Microsoft's Quicksand (QEMU plus Alpine). Pi, Claude Code or Codex can be pointed at any of them. An optional HTTP/HTTPS allow-list proxy limits which hosts the code can reach, and a credential-replacement mechanism lets authenticated calls work without giving the agent the secret. The stated aim is to make trying local models safer against mistakes and prompt injection. This is a short link post to a longer piece on the Prime Radiant blog, which I could not locate directly. ## Prompting and context techniques

- OpenAI, "Using GPT-6.2": prompting best practices and a prefix-edit warning — The guide's migration advice has two parts. First, from GPT-6.2 the API drops reasoning items when it detects prefix edits, a model downgrade, or a change of end user or organization. Answer quality can fall and token use rise, and prompt-cache eligibility is lost, so keep the prefix unchanged when changing settings between responses. Second, behaviours and suggested prompts for Astra and Sol: the default writing is more concise (revisit "be concise" in old system prompts); on unclear intent the model may stop to ask, so for long tasks give it room to make reasonable assumptions and continue; describe project coding conventions; specify imagery and typography for frontend work. A prompt block tells the model to write self-contained final answers that do not reuse reasoning shorthand or subagent jargon. OpenAI's own guidance has no published eval numbers on the page I read. Author: OpenAI developer documentation · Format: prompting guide · Length: about 15 min. Source: https://developers.openai.com/api/docs/guides/latest-model

- Addy Osmani on claude.dev: how the Claude Code team thinks about verification — Osmani says about 90% of the Claude Code team's code is written and reviewed by Claude, and that verification loops are what let you run dozens of agents in parallel instead of one or two. His ranking: end-to-end tests first (they are hard to fool), then property tests (round-trip, invariants, idempotency, equivalence) that cover edge cases the agent would not think of, and differential tests where the old system is the oracle for migrations. Concrete practices include a `verify` skill in `.claude/skills/` that boots and drives the app, stopping after three failing rounds to bring in a human, a 39-item reliability checklist whose triggers are read from the diff (usually 3 to 10 items fire), a `REVIEW.md` read from the base branch so a change cannot edit its own checks, and one tuned reviewer instead of several stacked ones. One internal number is given: a separate grader checking a rubric raised structured-file task success by up to 10 points over a plain loop. The numbers are from internal testing, and the post is published on an Anthropic-run site. Author: Addy Osmani, engineering leader (Claude Code team post) · Format: deep dive / how-to · Length: 10 min.
