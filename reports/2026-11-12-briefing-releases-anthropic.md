## United States

- Google releases Gemini Decision 1 and the Decisions API, a model that answers yes/no, multiple-choice and rubric questions with calibrated probabilities and bills no output tokens — Announced 11 November in Google AI Studio and the Gemini API (SDK 3.2 or later). One request carries a shared multimodal input (text, images, audio, video, PDFs, up to 262,144 tokens) and up to 1,000 independent typed questions; each answer returns a probability (yes/no is clamped to 0.01–0.99), per-option probabilities and a confidence score so code can route unsure cases to a human. Google says the model scores options in a single forward pass with 150–250 ms end-to-end latency (50–100 ms of model compute) and calls it nearly 5 times cheaper across a shared benchmark suite than Gemini 3.5 Flash-Lite on the Interactions API, with the lowest calibration error; those comparisons are Google's own and the blog does not publish the full tables. Price is $0.10 per million input tokens and $0 for output, with a no-cost tier in AI Studio. Google names internal uses: model-tier routing in Gemini Notebook (up to 40% lower latency on everyday queries), a safety layer for MCP tools in Search, and emoji selection in a Labs product. Integrations are rolling out in OpenRouter, LangChain, Vercel, LiteLLM, Pydantic AI, Pipecat, LiveKit and OpenCode. Why it matters: it turns a classifier-in-the-loop pattern into a priced API product and shows the control plane of agents being split off from the text-generating model; the same day, Ant's inclusionAI published an open decision model (see China), and Alibaba Cloud lists a decision-model-preview in its Model Studio. This follows OpenAI's Decisions API (reported 23 October); the new element is Google's pricing and calibration claim. Artefacts: API only (model gemini-decision-1; no weights) · Sizes or variants: one model, parameter count undisclosed · Released: 11 November 2026 (blog and Gemini API release notes). Source: https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/

- NVIDIA publishes an NVFP4 build of Moonshot's Kimi K3.1 Pro, a 2.8-trillion-parameter model, for Blackwell GPUs — The checkpoint was quantised with NVIDIA Model Optimizer v0.48.0 (routed experts in NVFP4, shared experts and the linear-attention layers in MXFP8, the rest BF16). The card gives the base model as a natively multimodal mixture-of-experts with 2.8T total and 104B active parameters and a 1,048,576-token context, and lists vLLM and SGLang as runtimes (SGLang instructions added 12 November). NVIDIA states it did not run a separate test pass for the quantised checkpoint, so no accuracy loss figures exist yet. Why it matters for readers who run models themselves: it is the first official lower-precision route for the largest open-weight Kimi, but the licence is the NVIDIA Open Model Agreement plus the Kimi K3.1 Pro licence, and it targets Blackwell only. Artefacts: weights (NVIDIA Open Model Agreement; base model under the Kimi K3.1 Pro licence), model card · Sizes or variants: NVFP4, about 1.4 trillion stored parameters in the safetensors metadata · Released: 10 November 2026 (release date stated in the card; repository files edited until 12 November). - Nex-AGI publishes Nex-N2.6, a 321-billion-parameter open-weight agent model built on GLM-5.3-Flash, and claims it almost stops looping — The Apache 2.0 FP8 checkpoint is a multimodal model aimed at computer use, coding and tool-heavy tasks, and the card says reasoning defaults to "max" effort, which matters when comparing token use. Nex-AGI reports, in its own internal checkpoint-replay test, reasoning repetition falling from 16.0% (Nex-N2.5-Pro) to 1.6%, and 100% valid tool selection among responses that call tools (82.2% for N2.5-Pro, 85.3% for GLM-5.3-Flash). The reliability tests were built from the team's own failure cases and are not independently reproducible. OpenRouter lists it at $0.12 per million input and $0.40 per million output tokens with 262,144 context. The team's GitHub organisation is named sii-nex and its community links are Feishu and WeChat, which point to a China-based team. ## Rest of the world

- Tether AI Research releases BotPsy-0.8B, a Qwen3.5-0.8B fine-tune for on-device tool calling, and reports it doubles the base model on agent benchmarks — The lab (the QVAC team at Tether) trained the 0.8B model in four stages with three kinds of feedback and reports BFCL v4 rising from 23.4 to 44.0, ACEBench from 30.1 to 58.7 and tau-bench from 23.2 to 51.5; it also says the model beats Qwen3.5-2B-Think (2.5 times its size) on five of six agent benchmarks, with Claw-Eval the exception (46.5 against 48.9), and reaches 86.1 on BFCL v4's hallucination tests, which check that the model declines when no tool fits. Instruction following improves from IFEval 59.7 to 90.8; red-teaming unsafe-response rate is 21% against 36% for the base. The blog's own weak-spot section says multi-step information retrieval remains poor (BrowseComp-Plus 4.5) and performance drops as instructions accumulate. All figures are Tether's. Apache 2.0, with BF16 weights and BF16, Q8_0 and Q4_K_M GGUF builds for llama.cpp and the QVAC SDK. Why it matters: a sub-billion model that can pick tools reliably is the building block for phone-side agents, and this is a clear test of whether the numbers hold in independent hands. Artefacts: weights (Apache 2.0), GGUF builds, blog with full benchmarks · Sizes or variants: 0.8B; BF16, Q8_0, Q4_K_M · Released: 11 November 2026 (blog published 11 November; repository created 10 November). - Amazon adds a standalone Web Search API to Bedrock AgentCore, backed by a web index Amazon operates — Announced 11 November: an InvokeWebSearch operation on the bedrock-agentcore data plane, callable from the AWS SDKs or CLI with ordinary IAM credentials and no gateway or resources to create first. It returns ranked results with a text extract, title, URL and publication time, supports domain include/exclude filters and a published-after date filter, and runs on the search infrastructure Amazon says also powers Alexa+, Kiro and Quick. Until now web search on AgentCore was reachable only through AgentCore Gateway as an MCP tool. The post gives no price or latency figures. Why it matters: agent builders on AWS can ground answers on an Amazon-owned index instead of a third-party search API, and the date and domain filters are the controls that prompt-injection defences usually need. Artefacts: API (preview details in the AWS post) · Sizes or variants: single operation · Released: 11 November 2026. Source: https://aws.amazon.com/blogs/machine-learning/introducing-the-web-search-api-on-amazon-bedrock-agentcore/
