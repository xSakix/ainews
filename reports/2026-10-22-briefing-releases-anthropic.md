## 1. United States

- Recursive releases Flint, a 39.8B-parameter coding MoE with about 2.5B active parameters, as Apache 2.0 open weights — Recursive says its small team and its "Eureka Machine" (a system that automates the research loop of proposing, implementing and testing ideas) built the model from scratch in under four months, and that the machine contributed to data, optimizers, training recipes and inference speed. The model card reports 54.9% on Terminal-Bench 2.1, 89.7% on SWE-bench Pro v2 and 74.2% on SWE-bench Verified (agentic scores averaged over at least five attempts; Recursive's own runs, comparison scores are developer-reported), and the blog claims it leads MoE models under 50B total parameters and runs more than 125 tokens per second on an M4 Pro MacBook Pro and more than 150 on a 64GB NVIDIA RTX Spark, up to twice as fast as comparable models. The tension for the reader is local versus hosted: the post says it "may need more guidance than the larger closed-source coding models you're used to". Architecture on the card: 49 layers (35 sliding-window, 14 full-attention), 256 routed experts with 6 selected plus one shared expert, 262,144-token documented context (the blog says up to 512k, recommends staying under 256k). The BF16 checkpoint is about 80 GB and runs on one B300 or H200 through an SGLang kit; Transformers modelling code is not included yet and quantised variants are "prepared separately". - Anthropic opens a research preview of Claude Duet, a proactive agent app for professionals and small-business owners — Duet is built around Claude Opus 5.5, runs in its own virtual machine with a browser so it keeps working when the user's devices are off, sends a morning brief, checks connected accounts "every few hours" (not continuously, to protect plan limits) and messages the user only when something needs attention. - Baseten's Base Labs releases mammoth-1 (27B) and elephant-1 (9B), open "decision models" post-trained from Qwen3.5 — Instead of generating text, a decision model returns a probability for every possible answer in one forward pass (choice, score or yes/no questions), so a ticket can be routed automatically above a chosen confidence and escalated to a person below it. Base Labs says mammoth-1 ranks first of 208 models on the Jev Decision Index 0.4 (71.24) and scores 65.9 on the Artificial Analysis Decision Index; elephant-1 is the top 9B model on Jev and ties for first on the Artificial Analysis index (65.2). The models are free to try for a week on Baseten Model APIs with zero data retention by default. It adds a third lab to the decision-model line that Liquid AI (d1, d1-ultra) and Cloudflare (Clef) already opened. ## 5. Tools, APIs and platform updates

- Anthropic releases API version 2026-10-21 and new major SDK versions, with breaking changes and an Apache 2.0 licence — Python SDK 2.0.0, TypeScript 1.0.0, C# 13.0.0, Go 2.0.0, Java 3.0.0, PHP 1.0.0, Ruby 2.0.0 and the `ant` CLI 2.0.0 now send the new version by default. The migration guide lists the breaks: Messages requests that send `temperature`, `top_p` or `top_k` return a 400 error even at default values (so a team that lowered temperature on a model that accepts other values, such as Claude Sonnet 4.6, loses that control, and no other setting replaces it; Claude 4.7 and later models already accepted only defaults); `document` blocks in assistant messages and `citations` on user-message text blocks return 400; Text Completions is removed from the TypeScript, Go, Java and Ruby SDKs and the CLI; client-side compaction is removed from the tool runner in favour of server-side compaction; the SDKs send the key as `Authorization: Bearer` instead of `X-Api-Key`, which can break proxies that read the old header; and the SDKs and CLI move from MIT to Apache 2.0 (earlier versions stay MIT). On Amazon Bedrock the new version works only with Claude 4.7 and later. The platform notes add `enforcement_status` fields on user profiles (launched 20 October) so a platform can see whether Anthropic has restricted one of its end customers. - IBM open-sources vLLM-Hook MIA, a vLLM plugin that reads and steers a model's internal activations at inference time without giving up CUDA-graph speed — Most interpretability tools need Python code inside each layer, which forces vLLM into slow "eager" mode. MIA instead puts GPU operators in place before the graph is captured; a scheduler writes routing entries at fixed GPU memory addresses and a courier moves captured data to the CPU. IBM's technical report says it is up to 20 times faster than the first vLLM-Hook and up to 14 times faster than a code-insertion method, with steering overhead of about 2% on an 8B Llama and a 1.5B Qwen model and 6% on Llama 70B (IBM's own measurements). The use case is run-time guardrails: decline a malicious prompt, flag a hallucinated fact, or edit tone. Artefacts: code (GitHub IBM/vLLM-Hook), technical report (PDF in the repository), blog post · Sizes or variants: vLLM-Hook MIA · Released: 21 October 2026. Source: https://research.ibm.com/blog/fast-interpretability-plugin-vllm
