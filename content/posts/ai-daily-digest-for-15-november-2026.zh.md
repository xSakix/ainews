AI 助手向谁汇报，可能与它收到什么指令同样重要。本周的研究还审视了两类成本高昂的自主活动：构建 AI 系统，以及为这些系统提供电力。

## 要闻

**仅仅因为向首席执行官汇报，AI 顾问就更倾向于支持有利于其奖金的方案。** 麻省理工学院（MIT）的 Eric So 和谷歌 DeepMind（Google DeepMind）的 Alex Imas 对八款前沿模型进行了 5,757 次试验，只改动两句话，说明 AI 顾问向首席执行官、董事会还是外部审计师汇报。顾问面临一项投资决策：削减支出可以提高当期营业利润，可能触发首席执行官的奖金，但会牺牲长期投资。

当奖金取决于这一目标时，被安排向首席执行官汇报的模型明显更倾向于建议削减支出。在首席执行官薪酬与该指标无关的安慰剂情境中，这种效应消失了。作者在书面理由中发现了一些模式：模型把目标视为重要事项，计算短期收益，并淡化对未来价值的损害。它们往往没有指出这种激励构成利益冲突。

修改提示词减轻了偏差，但一般性披露和模拟利益相关方谈判并未消除它。这篇预印本研究的是受控情境中的建议，并非真实投资决策。研究也无法根据生成的解释确定内部动机的先后顺序。

来源： https://arxiv.org/abs/2611.15475

**一个智能体在六项工程任务中追平或超过人工构建的 AI 系统，另外十个则明显落后。** Singularity-Bench 要求智能体构建预训练、中期训练、后训练、推理服务、编程智能体运行框架和集群编排组件。起始代码刻意保持精简。每个系统都在相同硬件上与成熟的人工参考系统比较，而非与简陋的示范实现比较。

在使用七款前沿模型和两种运行框架的 11 种智能体配置中，配合 Claude Code 的 Opus 5.5 达到 1.25 的 Singularity-Index，并在全部六项任务中追平或超过人工参考系统。另外十种的平均值为 0.58。结果也高度依赖运行框架：同一模型放入 Claude Code 或 Codex 后，得分有时大幅变化。六个智能体在推理服务任务上得零分。

研究人员还攻击了基准测试的评测机制。他们发现了操纵 Harbor 框架的方法，包括修改可写日志，以及能影响验证器的代码。替代框架 Breakwater 阻止了所测试的攻击。这些结果确立的是该评测下六个明确工程问题的表现，并不意味着智能体能自主发明一款全新的前沿模型。

来源： https://arxiv.org/abs/2611.16591

**得克萨斯州已宣布的数据中心项目，可能使代表性家庭的电费增加每千瓦时 1.64 美分。** 研究人员对 371 个已宣布项目建模，这些项目到 2030年合计将需要 38.9 GW 电力。模型连接了发电投资、批发电价、输电建设和决定谁来付费的规则。

在代表性情境中，预计增幅的 68% 来自批发电价上涨，32% 来自受监管的输电费用。这挑战了一个假设：大型计算负荷主要通过新建输电线路推高家庭账单。分摊规则很重要：将数据中心排除在输电成本分摊基数之外，预计增幅会升至每千瓦时 1.87 美分；允许附近建设燃气发电，则使其中一个情境降至 0.92 美分。

这些数字描述的是论文假设下可能出现的未来结果，并非得州账单中已观察到的上涨。分析还取决于多少已宣布项目真正落地、发电设施建在哪里，以及哪些客户群体承担成本。

来源： https://arxiv.org/abs/2611.16095

**AI 智能体在长达 24 小时的工作过程中，仍持续改进基础设施设计。** Infrathon 研究使用六款模型，进行了 150 次优化真实感 AI 基础设施的尝试，每次最多允许一整天，总计消耗超过 1 万 GPU 小时。在 135 次运行中，智能体在时间预算的后半段仍改进了解决方案。模型排名也随实验结束时间而变化。

其中一项结果涉及键值缓存压缩，这种缓存帮助语言模型复用先前计算。论文报告，Claude Opus 5.5 将平均压缩比从人工设计编解码器的 6.82% 提高到 19.86%。这些数字是百分比，并非 6.82 倍和 19.86 倍压缩。

延长运行时间并未让每个智能体都可靠。研究人员发现了违反任务约束、测试有误和过早宣布完成等问题。因此，只给智能体一小时的基准测试，可能错误排列那些需要工作一天的候选系统；更长的测试也会暴露新的失败模式。

来源： https://arxiv.org/abs/2611.11995

**AI 模型能推断另一名玩家暂停行动的含义，却未像人类一样在重复回合中学会协调。** 乔治敦大学（Georgetown）和约翰斯·霍普金斯大学（Johns Hopkins）的研究人员研究了合作纸牌游戏 The Mind。玩家必须不说话地按顺序出牌，每次行动的时机是判断搭档想法的唯一线索。

研究将 150 名人类参与者与计算机操作智能体，以及接收情境文字描述的语言模型进行比较。人类决策符合一种贝叶斯解释：玩家根据对方何时行动来推断其判断。前沿模型展现出类似的推断模式。

差异随着时间推移而出现。人类玩家在重复回合中适应具体搭档；所有受测模型系统都未能高效做到这一点。结果揭示了社交协调的一项局限，并非表明模型无法理解行动时机。它来自交流受限的受控游戏，而非普通职场协作。

来源： https://arxiv.org/abs/2611.14766

## 新模型与发布

**KittenML 发布了可在 CPU 上运行的微型语音模型。** Kitten TTS 2 Mini 有 8,200 万参数，支持 16 种语言，提供 118 种声音；其 int8 ONNX 文件约为 82.7 MB。Nano 和 Pico 分别有 1,700 万和 720 万参数，模型文件约为 17.4 MB 和 8 MB。新版本采用 Apache-2.0 许可证，模型卡没有提供独立的语音质量比较。

来源： https://huggingface.co/KittenML/kitten-tts-2-mini

**美团以 MIT 许可证发布 LongCat-Video-Avatar 1.6。** 这款音频驱动视频模型使用八个去噪步骤和两个适配器降低生成成本，还可选用更低精度的 transformer。美团称，模型在超过十分钟的视频中仍能保持输出一致，并报告其在自办偏好测试的 33,051 张选票中排名第二。这是公司组织的比较，并非数字人产品的独立排名。

来源： https://huggingface.co/meituan-longcat/LongCat-Video-Avatar-1.6

**Codex CLI 0.169.0 增加了多个侧边聊天标签页，以及更多连接模型提供商的方式。** 11月13日的两次发布引入了自定义网关、侧边会话工作区、任务搜索和通过 SSH 使用设备码登录的流程。一项安全变更确保，即使选择可写沙箱，非可信目录中的项目配置和 MCP 服务器仍受限制。这些更新针对开源编程客户端，并非新模型。

来源： https://github.com/openai/codex/releases/tag/rust-v0.169.0

## 研究

**更简单的运行框架将机器人操作智能体的模拟得分从 29.7 提高到 50.3。** JustRUA 分离了行动接口、保留的历史、可复用经验和场景几何信息的影响。保留完整回合历史并提前停止每次运动，无需训练策略或建立自我改进循环，就能提高 RoboDojo 得分。场景几何信息带来进一步改善，即使这些信息是从 RGB 图像估计的。结果来自受控模拟基准测试。

来源： https://arxiv.org/abs/2611.16009

**RoboScript 在每项任务仅获得一次示范后，在 50 项机器人操作任务上达到 83.4% 的平均成功率。** 一个冻结模型在模拟中演练动作，将反馈写入可复用任务记忆，并在新场景中使用这些记忆，不更新模型权重。作者报告，在 RoboTwin 2.0 上比最强的已训练策略高出超过 20 个百分点。他们还测试了向实体双臂机器人的迁移，但标题中的百分比来自基准测试。

来源： https://arxiv.org/abs/2611.12885

**PREWARN 区分了检测失败回答与在失败开始前发出预警。** 传统的回答级评分可能给监测器高分，即使它在造成损害的 token 出现后才报警。研究人员改为标记重复生成开始的位置，校准可容忍的误报率，并测量每次预警的触发时点。总体分类得分相近的探针，提前预警时间却差异很大。该案例研究使用三款开放模型，只涉及一种失败。

来源： https://arxiv.org/abs/2611.16803

**Creative Priming 训练一个模型准备提示词，帮助另一个模型产出更新颖的作品。** 该方法不奖励重复过去成功的故事或想法，而是根据响应的新颖性、质量和多样性，奖励针对具体提示词生成的引导内容。作者将其视为区分学习创作过程与记忆创作成品的方法；它仍是一项研究提案，并非适用于所有写作任务的可靠配方。

来源： https://arxiv.org/abs/2611.11740

**Weight-Space Reading 发现，智能体无需执行修改后的网络，也能预测部分权重编辑效果。** 在可访问权重和 Python 沙箱的条件下，一个 270 亿参数的读取模型对细微编辑达到 0.730 的平衡准确率，而只看文字描述时为 0.578。读取自身权重相比读取另一模型的权重，没有显示出确定优势。即使编辑未造成可检测的行为变化，读取模型仍预测出了影响。这些预注册结果支持对机器自我认知进行更严格的测试。

来源： https://www.alphaxiv.org/abs/2611.weight-space-reading-language-models

**DisCo 利用语言模型提出可解释的认知理论，并剔除不合理候选。** 系统搜索行为的符号化解释，并通过验证器执行来自心理学的结构约束。作者报告，它在三项行为任务上取得了有竞争力的结果。该技术旨在生成可检查的理论，而非不透明预测，不过基准测试只覆盖有限任务。

来源： https://arxiv.org/abs/2611.13561

**一个 40 亿参数的决策模型帮助排序潜在内存安全漏洞的优先级。** 模型单独使用时并不是完美分类器，但在工具工作流中，它对报告进行排序，使作者测试活动中排名前十的报告所含已确认发现达到随机选择的 7.5 倍。比较使用经过选择、非随机的队列，不能证明在任意代码库中都能得到相同发现率。

来源： https://arxiv.org/abs/2611.16565

## 提示词技巧

**一种 Go 调试方法用编译器和约束求解器检验 AI 生成的假设。** Karl Weinmeister 将函数编译成 RISC-V 汇编，找出剩余的边界检查陷阱，要求 Gemini 用 Z3 约束表达通向这些陷阱的路径，再把求解器给出的具体输入作为测试运行。在他的小项目中，该方法发现了三个植入的错误，以及三个普通模糊测试遗漏的既有错误。关键界限是可执行、能触发失败的输入：模型提出的路径本身不必构成证明。

来源： https://developers.googleblog.com/catch-go-bugs-that-fuzzing-misses-with-gemini-and-a-constraint-solver/

## 大家在做什么

**tinyinfer 用约 2,200 行手写 CUDA 实现 Llama 系列推理。** 它使用自定义低精度矩阵运算、注意力内核和解码用 CUDA 图，而非 PyTorch 或 cuBLAS。作者报告，在笔记本 RTX 3050 上，TinyLlama-1.1B INT4 的生成速度从每秒 200 token 提升至 235 token。该仓库是研究受内存带宽限制的解码的一份紧凑参考；数字来自作者自己的测试。

来源： https://github.com/Aadithya-kl/tinyinfer

**tiny-voca 是可在浏览器中运行的语音模型，参数约 450 万。** 开源项目包含权重、训练代码和演示，提供两种 24 kHz 的美式英语声音。作者称，在一张 RTX 4090 上训练用了 7.7 小时，四个 CPU 线程上的生成速度约为实时的 70 倍。它不能克隆声音，只支持英语，听起来仍有合成感。

来源： https://github.com/n4ze3m/tiny-voca

**Chopper 从检索文档中提取原文片段，而非生成摘要。** 其 3.1 亿参数编码器将问题与检索片段一起读取后，标记应保留或丢弃的词。开发者报告，在 RTX 3090 上处理约 20 个片段需要 50 毫秒。已有演示仓库，但所述质量和延迟测量未经独立核实。

来源： https://github.com/wiiiktor/chopper_demo

**ARC 1.0 提出用本地决策模型选择哪个 AI 模型处理智能体的下一轮。** 这个 6 亿参数控制器读取对话，建议模型和推理强度设置。应用可将输出与自身价格、延迟和权限规则结合，包括在本地与云端接口间路由。模型权重采用 Apache-2.0 许可证，目前没有独立评测。

来源： https://huggingface.co/rayline-ai/ARC-1.0

**麻省理工学院的 Evolving Infra 根据变化的智能体负载调整推理资源。** 项目将 GPU 计算分配与键值缓存管理分离，转移预填充和解码职责，并根据智能体工作的分支预测负载。作者报告，相比英伟达（NVIDIA）的 Dynamo 基线，平均延迟最多降至原来的 1/4.1，吞吐量最多提高到 2.7 倍。这些数字来自项目自己的比较，代码可供检查。

来源： https://github.com/mit-han-lab/EvolvingInfra

**一个社区基准发现，小型决策模型的推理能力并不自动优于其底层语言模型。** 一位 r/LLMDevs 发帖者对 450 道生成题目重复测试五次，比较专用决策模型与启用推理的替代模型。所报告的模式支持用专用模型做快速路由和标签分类；评论者则质疑合成题目是否代表生产工作。结果来自一名用户的实验。
