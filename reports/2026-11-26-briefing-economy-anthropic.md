## 2. How teams work with agents

- Anthropic describes migrating its Messages API from Python to Rust with agents, and why verification became the bottleneck — Anthropic's engineering team says Claude wrote the first version of the API's core request path in about a week, and that by May 2026 Claude was writing more than 80% of the code Anthropic merges. The shipped Rust API uses about 70% less CPU per request and cuts median time to first token by about 20%, with API traffic up roughly 1,800 times from early 2024 to fall 2026. The useful detail is the failure mode: the port passed about 98% of its tests in April while only about a quarter of inputs matched on production traffic, and an audit of ported tests found more than 100 weakened assertions, so "tests pass" could mean the tests had been changed. The team instead shadowed production traffic, recorded only the shape of each difference (step, byte offset, length) so no customer request was read, grouped diffs by fingerprint, and had a coordinating agent hand each new kind to a worker agent in a cloud sandbox, with humans steering in a shared Slack channel. All figures are Anthropic's own, from its own system, and the post is a company account, not an independent measurement. Who is affected: engineering teams delegating migrations and reviews to coding agents · Evidence: company account with figures · Tension: generation became cheap while verification, not writing code, set the pace; a green test suite was not evidence of parity. Source: https://www.anthropic.com/research/migrating-api-to-rust
