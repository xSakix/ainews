## Essays and arguments

- Why Are Coding Agents So Dumb? — Michael Lynch argues the agent harness, not the model, is the bottleneck in AI-assisted coding. His examples: agents run ten embarrassingly parallel subtasks one at a time, declare work finished early, and lack secrets-proxying, session driving and quota-aware model choice. He lists the features he wants from an ideal harness and offers a principal-agent explanation: lab executives optimise for demos and model benchmarks that barely measure the harness. The argument is his opinion and rests on his own use of Claude Code, Codex, OpenCode, Cline and Pi. Author: Michael Lynch, independent software developer (mtlynch.io) · Format: essay · Length: about 10 minutes. Source: https://mtlynch.io/why-are-coding-agents-so-dumb/
- What agents mean for Rust (and vice versa) — Niko Matsakis, a long-time Rust language designer, argues that programming-language design still matters in the agent era. His case: Rust's performance defaults plus a profiler give agents a tight benchmark-profile-propose loop, and its type system keeps agents on track but cannot establish correctness, so tests and specification stay necessary. He then lists changes Rust could make to suit agentic work. It is a post companion to his talk at REBASE (SPLASH) this week, and his claims are his own judgement. Author: Niko Matsakis, Rust language designer · Format: essay · Length: about 13 minutes. Source: https://smallcultfollowing.com/babysteps/blog/2026/10/14/agentic-dev-and-rust/

## Prompting and context techniques

- Your Game Is A Harness — Kyle Kukshtel's blog version of a conference talk on making a game legible to coding agents, from daily use in game development. The concrete techniques: one seeded source of randomness so any state can be recreated exactly; data-oriented content and binary isolation so no compile step is needed; and profiler output dumped as text (he uses the free samply) so an agent can read captures and iterate in seconds. His claim is that the agent loop is only as good as how much of the game it can read as text. He notes in a postscript that he shipped a small project without any of this, so it targets larger games. Evidence is the author's own workflow, not a controlled test. Author: Kyle Kukshtel, game developer · Format: deep dive (talk write-up) · Length: about 25 minutes. Source: https://kylekukshtel.com/ai-harness-engineering-game-development-claude-code
