## Local models and agents

- Nari Labs ships NariQ, a sub-3-bit quantisation of Qwen3.8-27B that it says matches BF16 on agent tasks — Nari Labs applied trellis-coded post-training quantisation, calibrated on real coding-agent traces, to Qwen3.8-27B (released 20 November). The 3-bit file is 10.12 GB against 53.8 GB for BF16. The authors' own table (BF16 / 3-bit / 2.5-bit / 2-bit): DeepSWE v1.1 pass@1 39.8 / 41.0 / 41.9 / 28.6; Terminal-Bench 2.1 62.6 / 63.8 / 60.2 / 52.4; AIME 25+26 97.7 / 98.3 / 96.5 / 86.0, so the "BF16-level" claim holds for 3 and 2.5 bits and not for 2 bits. Catch: the files need Nari Labs' own llama.cpp fork (stock llama.cpp, Ollama and LM Studio cannot load them), the fork is tuned for SM120 GPUs, is slower on Ampere/Ada/Hopper, unsupported on AMD and Intel, and slow on Metal; the vision tower and KV cache stay BF16. All numbers are the lab's own. Built by: Nari Labs (author Doyeob Kim) · Artefacts: weights on Hugging Face (Apache-2.0), technical report, llama.cpp fork · Signal: 133 HN points. Source: https://huggingface.co/nari-labs/Qwen3.8-27B-NariQ-GGUF

- Gall: a from-scratch Rust and Metal engine that keeps a 26B mixture-of-experts model on a 24 GB MacBook Air by unloading it after every answer — Gall runs Thinking Machines' Inkling-2-Mini (26B parameters, about 3.4B active, 12.7 GB download) behind a local OpenAI-compatible API from a menu-bar app. The trick is an "instant unload": one second after each answer it saves the conversation state to disk and releases working memory, so the process idles at about 32 to 57 MB and reloads warm in about 0.1 s (first token with a saved prefix 0.5 to 1.2 s; only conversations of 512 tokens or more reuse saved state). Measured on an M2 Air: about 20 tok/s at short context, 16 to 16.5 tok/s at 29.9k context, roughly 10% throttling after 2.5 minutes on the fanless machine. Catch: tested on one machine only; the 100k context setting was never measured above 29.9k; model quality is not evaluated (the accuracy check only compares against a patched llama.cpp); the optional Telegram bridge hands messages to a coding agent that runs as your user with no approval prompts; the build is not notarised. Built by: ltrgoddard · Artefacts: code (MIT; parts derived from llama.cpp/ggml) · Signal: 7 stars, 7 HN points. Source: https://github.com/ltrgoddard/gall

- NukeTorch claims 517 tok/s for Qwen3.6-35B-A3B on a MacBook Pro, but it is source-available, not open — A C++ and Metal runtime for Apple silicon (4-bit Qwen3.6-35B-A3B plus a draft model) with an OpenAI-style local API. Vendor-run benchmarks report 482.7 to 597.5 tok/s single-request across four prompts (coding prompts, one request at a time) and 821.8 tok/s aggregate for eight concurrent users, 3.9x to 6.8x faster than mlx-lm, 2.9x to 5.5x than llama.cpp and 1.0x to 1.4x than oMLX. Catch: each test is a single run, competitors ran at default settings, some use up to 36% more memory than mlx-lm, the README says the two papers it cites do not explain its speeds, and the licence bars offering the functionality to others (free only for personal use, education and firms under US$10M revenue and 250 staff). Wants an M5 Max with 48 GB; forced tool choice and `response_format` are unsupported. Built by: NukeTorch (no named authors) · Artefacts: code/binary under a restrictive licence · Signal: 0 stars, 1 HN point. Source: https://github.com/NukeTorch/Qwen3.6-35B

- please: a local "polite LLM for the CLI" that keeps weights on your laptop and bridges into remote shells — `please` turns natural-language instructions into commit messages, one-off scripts, formatting and merge-conflict resolution, using Inkling-2-Mini (IQ4_NL GGUF) with all inference local. The interesting part is the bridge: run it inside an SSH session or Docker container while inference stays on the host, over a forwarded socket. Catch: the README does not mention the Metal 4 engine the HN title promises or give a licence; no benchmarks. Built by: xhjkl · Artefacts: code, Homebrew install · Signal: 25 stars, 3 HN points. Source: https://github.com/xhjkl/please

- pi-protokoll: each turn ends with a model-written "protocol block", so compaction in the Pi coding agent takes about 30 seconds instead of re-summarising history — An extension for local-model users: the summary is assembled continuously in three tiers (recent turns verbatim, older turns in detail, a status tier with index, rules, open items and files) with lookup tools for earlier turns. The author reports, on Qwen3.x with 2x RTX 3090 and 262k context, 22 compactions over 118 turns each cutting context from about 213,000 to 35,000 tokens in about 30 s, and 99.8% of prompt tokens in the median request served from prefix cache over a 12-day session. Catch: author's own numbers, Qwen3.x only; the model sometimes omits the block on long tool-heavy turns, and invents its own context-fill level (mitigation unmeasured). Built by: sebion7125 · Artefacts: code (MIT) · Signal: 9 stars, 1 HN point. Source: https://github.com/sebion7125/pi-protokoll

- radiance-gfx9: a probe of whether old AMD Vega cards (MI25, Vega 56/64) can join a new inference engine — Device kernels for gfx900 written against the radiance engine's plugin ABI. Six ops pass; `add` is bit-exact on 10 of 10 cases (relative L2 error 0 versus 6e-3 for the engine's own AVX-512 library), `silu_mul`, `rmsnorm` and `gemm_nt` bit-exact up to stated sizes. Catch: no model runs end to end (rope, paged attention, kv_store, logits GEMM unwritten), no throughput measured, the 1.2 to 2x prefill speedup over llama.cpp's Vulkan path is a projection, bf16 is emulated, and the author says it may end as a negative result if fp16 GEMM cannot reach 1.3x the Vulkan baseline. Built by: Sophia-Thickums · Artefacts: code (Apache-2.0) · Signal: 0 stars, 2 HN points. Source: https://github.com/Sophia-Thickums/radiance-gfx9

- Ignis: a browser-native LLM and multimodal inference engine — Runs on WebGPU, WebAssembly and OPFS; offered models are Spark-X2.6 1.7B (1.3 GB) and 4B, and LFM3-Omni 2B for vision, audio and voice, plus custom `.ignis` model URLs. Catch: the page gives no speeds or licence; only a demo and a repository link (github.com/Ray-D-Song/Ignis). Built by: Ray-D-Song · Artefacts: demo, code · Signal: 1 HN point. Source: https://ignis.ray-d-song.com/

- L.A.T.E. (Local AI Tool Engine): make small local models reliable by moving planning into plain code — Rules split a request into clauses and call tools (exact math, dates, units, search, files, memory) with values passed between steps; only if parsing fails does the model propose a JSON plan, and only as a last resort does it pick one tool at a time. For models of 8B or smaller the model mostly writes the final text. Node.js, two dependencies, works with Ollama, LM Studio, Groq. About 470 tests and a 45-prompt eval (35 need no model). Catch: real-model testing was by hand on older rounds (qwen2.5:3b, dolphin-mistral, Groq); recent changes were checked only with fake models; DuckDuckGo scraping without an API key can break. Built by: ikaushik817 · Artefacts: code (MIT) · Signal: 1 star. Source: https://github.com/ikaushik817-art/local-ai-tool-engine

- OCRia-nano-1: LlamaIndex's 8.1M-parameter CPU document parser, distilled from its 4B document model — OCR stack (3.9M parameters: line detector, script router, four recognisers) plus LayoutNet (4.27M) for tables and layout, running inside the open-source LiteParse. On ParseBench-2 it scores 59.2 against 55.1 (Indra), 52.5 (Marker) and 48.7 (LiteParse with Tesseract); 27.8 pages/s on 16 vCPUs, 426 ms per page on one core. Catch: authors' own results; Indra is faster (29.6 pages/s); chart score 3.1 against 77.4 for the 4B teacher; not standalone; weights carry a custom licence (free for research and for organisations under US$2M revenue and funding). Built by: LlamaIndex (Logan Markewich) · Artefacts: weights, technical report, LiteParse (Apache-2.0) · Signal: 9 HN points. Source: https://huggingface.co/llamaindex/OCRia-nano-1

## Open-source projects and tools

- OpenToolSearch: a 0.6B reranker plus 0.6B embedder for choosing tools in large agent tool catalogues — Fine-tuned from Qwen3-Reranker-0.6B. nDCG@10 is 70.8 on public ToolRet (a Google model scores 73.5, Tool-DE 72.0), 89.0 on the authors' own OTS-MCP-1k (Tool-DE 91.4); cost $0.19 per 1,000 searches, median 0.10 s at full throughput. The authors say "quality is competitive, not first", tell readers to weight their own set below the public one, and suggest simply giving a model the full list for catalogues of about 200 tools or fewer. English-centred, skills tested only on a small private set. Built by: AI3 Inc. · Artefacts: code and models (Apache-2.0) · Signal: 7 stars. Source: https://github.com/ai3inc/opentoolsearch

- judge-audit: how much of a human's work can an LLM judge safely take over? — Replays decisions humans already made and reports the share a judge could automate at a chosen error rate (1, 2, 5 or 10%), the confidence threshold to deploy, and a held-out upper bound; no LLM inside the measurement. On BANKING77 at a 5% target, one judge automated 41.0% with a 3.9% bound, but the share ranged 27.0 to 45.1% across split seeds and at some splits the bound exceeded 5%. In the 12-judge multilingual transfer test, bounds ran above 5% in 5 of 6 tests ("that is not a pass"). Catch: public datasets probably seen in pretraining, mostly single runs, label noise unmeasured, and the author states no outside reviewer has read the study plans. Built by: kunko-ai-labs · Artefacts: code (Apache-2.0) · Signal: 14 stars, 2 HN points. Source: https://github.com/kunko-ai-labs/judge-audit

- CubePod: a self-hostable, E2B-compatible agent sandbox whose root filesystem survives restarts — Kata microVMs on Kubernetes, with writable OverlayFS state and `/workspace` on two raw block volumes, Rust in-guest daemons, a Go controller and gateway, and an egress proxy that swaps `cpodref_` placeholders for real credentials so agents never hold secrets. Claims: warm-pool claim under 50 ms, cross-node resume about 1 s, copy-on-write fork under 1 s. Existing E2B SDK code works by changing `E2B_DOMAIN`. Catch: latencies are self-reported with no methodology, it needs Kubernetes with Kata and a CSI driver, no releases published. Built by: cubeplexai · Artefacts: code (Apache-2.0) · Signal: 77 stars, 1 HN point. Source: https://github.com/cubeplexai/cubepod

- Anvil: a native macOS coding agent for almost any model — SwiftUI app (macOS 15+, Xcode 26+) with per-diff review, checkpoints and rewind per request, sub-sessions in separate git worktrees, built-in terminal, browser preview, iOS Simulator control, MCP and skills. Works with any OpenAI-compatible endpoint, Ollama, LM Studio and provider presets. Catch: version 0.1.0, build from source, its ChatGPT and Gemini web-account providers use private endpoints that can break and may breach those services' terms; the eval is the maintainer's own 16-task suite. Built by: deeeeone · Artefacts: code (AGPL-3.0) · Signal: 45 stars. Source: https://github.com/deeeeone/Anvil

- Agentic Algorithm Engineering (AAE): a Claude Code/Codex skill that optimises code by stating a falsifiable hypothesis before each experiment — From Heidelberg University's Algorithm Engineering group: the agent and user fix the benchmark, metric, correctness assertions and budget; then each cycle predicts the metric change, makes a minimal commit, keeps it only if faster and still correct, and otherwise reverts. Outputs numbered patches, a PDF report and a lessons file. Reported: 8.9x on VieCut with identical cuts, 3.9x on KaHIP kaffpa with unchanged quality, 3.0x on a pseudoflow max-flow code (verified on 164 instances), 1.82x on FREIGHT, 1.61x on ParHIP; the kaffpa session ran 122 experiments and kept 41 patches. Catch: correctness is only as strong as the assertions agreed at setup; results are from specific sessions on research codes; comparison table is the authors'. Preprint arXiv 2609.07204, "to appear" at DIMACS 2027. Built by: Heidelberg Algorithm Engineering Group · Artefacts: code (MIT), paper · Signal: 3 HN points. Source: https://chszlab.github.io/AgenticAlgorithmEngineering/

- mcpwatch: a lockfile and runtime guard against MCP "rug pulls" — `mcpwatch lock` pins the tools and descriptions your `.mcp.json` servers expose; `mcpwatch check` fails CI if a pinned tool changes (with `--live` showing the changed sentence); `mcpwatch guard` blocks changed tools at runtime. The service also fingerprints servers in the official MCP registry daily and grades them for leaked secrets, plain-HTTP endpoints and poisoned descriptions. Catch: grades are "not a guarantee of safety"; how the fingerprint is computed is not explained; the company sells monitoring, and the page does not say which features are paid. Built by: anardimontlv (mcpwatch) · Artefacts: code (Apache-2.0 per the page), CI action, demo · Signal: 1 HN point. Source: https://www.mcpwatch.io

- slop-deps: catch hallucinated package imports before install — Statically scans JS, TS, Python, Rust and Kotlin sources and manifests, checks names against a bundled corpus of 4,179 popular packages, probes npm, PyPI, crates.io and Maven, and flags typosquats by edit distance and homoglyphs; `--fix` can attempt AI-assisted repair. Zero runtime dependencies, 96 tests. Catch: the README says all code was written by AI agents under human direction; a small bundled corpus; the example output (2 flagged, 140 clean, 142 ms) is illustrative. Built by: Vidit Patil · Artefacts: code (MIT) · Signal: 2 stars. Source: https://github.com/viditx/slop-deps

## Agents and automation

- Minymaton: a durable message bus so coding agents (Claude Code, Codex, Copilot CLI and others) can talk across sessions — Rust with bundled SQLite; messages are committed before `publish` returns, each subscription keeps its progress across restarts, and a parked `receive` wakes on a commit instead of polling. Five tools (stream, subscription, publish, purge, receive); receive results capped at 16 KiB. Catch: not exactly-once (agents dedupe by `batch_id`), waking an idle session needs a helper and a harness that reports background-command completion, one loopback server (remote use via SSH tunnel). The "token waste" claim in the title is not quantified. Built by: immutlex-dev · Artefacts: code (AGPL-3.0, v0.1.6 on crates.io) · Signal: 7 stars, 3 HN points. Source: https://github.com/immutlex-dev/minymaton

- ELBI: an "empirical memory" for data agents — The agent saves a finding as a derivation, a Python function with declared inputs, stored with its result and lineage and exposed over MCP as a cached, versioned tool; derivations are recomputed when the underlying data change, and 30-plus `verify_*` tools return sound, unsound or inconclusive verdicts. The README cites SleuthBench (arXiv 2609.34228): handing six frontier models precomputed statistical artifacts raised accuracy on feature-outcome questions from 41.9% to 68.0%. Catch: self-reported; the quick-start dataset has three rows; a hosted commercial product sits behind it. Built by: Intelligible · Artefacts: code (Apache-2.0), `uv tool install elbi` · Signal: 39 stars, 4 HN points. Source: https://github.com/Intelligible/elbi

- Agent First Browse: delta snapshots to cut a browser agent's token use — Emits only added, changed and removed controls between consecutive steps on the same page, and prunes occluded elements behind a modal; runs as a LangGraph agent or as an MCP server/CLI for another agent. Self-reported: session average 754.2 to 341.1 tokens per step (54.8% fewer), up to 95% fewer with a blocking modal, latency 1,164 ms to 97 ms. Catch: a small set of scenarios on headed Chromium, no independent check; the "zero API" mode just hands reasoning to your own agent. Built by: SandeepAi369 · Artefacts: code (Apache-2.0) · Signal: 25 stars, 2 HN points. Source: https://github.com/SandeepAi369/Agent-first-browse

- shoebox: agent orchestration with nothing but folders, Markdown and Docker — Each agent is a folder (instructions, tools, Docker image); tasks are Markdown files moved between `kanban/` statuses, cron jobs are Markdown files, git tracks agent definitions and memory, and it uses the Pi harness with a terminal UI, optional web or Telegram. Author claims about 1.4k lines of code and under 100 MB idle memory. Catch: self-reported size figures, needs Docker and a provider API key, 4 stars. Built by: ameesme · Artefacts: code (MIT) · Signal: 4 stars. Source: https://github.com/ameesme/shoebox

- Gal: a single-binary local agent runtime with a kernel-enforced sandbox — Runs on Linux, macOS and Windows for CLI, desktop, browser, chat and HTTP, claiming no Python, Node or Docker. Control comes from sandbox policy, hooks that can deny or confirm tool calls, and `/sudo` to lift limits for a turn; sessions save after each agent round. Catch: the HN title promises "per-call permissions and rollback", but the page describes neither rollback nor per-call prompts (it says explicitly there are none); no licence ("all rights reserved"), liability disclaimed, release repo only. Built by: GAL team · Artefacts: binaries (release repo gal-agent/gal-release), docs · Signal: 4 HN points. Source: https://agent-home.ai/index.html

## Experiments, demos and write-ups

- TTLM: a 22,000-weight ternary transformer that talks, on a computer with no CPU — Runs on a Gigatron TTL (an 8-bit machine built from about 30 logic chips) emulated cycle by cycle in the browser. 2 layers, width 32, 2 heads, 21,984 ternary weights (about 9 KB), 155-word vocabulary, 20-token context; integer-only, and the Python reference matches the Gigatron program's output exactly. Weights and conversation memory live in the screen's coloured noise. Speed about 0.5 words/s in the browser, roughly two seconds per word at real hardware speed. The persona is a moth that knows about 150 words, mostly light and warmth. Catch: a toy, by design; it demonstrates feasibility, not usefulness. Built by: storagebits (on the Gigatron by van Kervinck and Belgers; simulator by Philip Thomas) · Artefacts: demo, source, training code, real-hardware build · Signal: 2 HN points. Source: https://storagebits.github.io/ttlm/

- Rumor Village: a 100-villager rumour simulation driven by a fine-tuned local model — A C++ engine embeds llama.cpp and batches decisions for all neighbours; Gemma 4 E4B (instruction-tuned) fine-tuned by the author to emit JSON actions constrained by a grammar and validated against rules; integer-only simulation so a seed replays identically. Author's benchmark (1,000 decisions per language): invented memories about 2% to 0%, failures 16.5x fewer in Spanish and 5.0x fewer in English, prompts 921 to 256 tokens, LLM-judged naturalness 3.6-3.7 to 4.1-4.2; rejected actions slightly worse (about 0.1% to 0.9-1.0%). Catch: dataset and fine-tuning pipeline not published, results unverified, needs CUDA or Vulkan (a dice-based mode runs anywhere), Windows builds unsigned. Built by: Manuel García Sanz · Artefacts: code (MIT), model (Apache-2.0, 5.34 GB Q4_K_M GGUF), assets CC0 · Signal: 17 stars. Source: https://github.com/manuelgscom/rumor-village

- Terminal Tasks Open: a 30-task terminal benchmark released with an audit that finds defects in 23 of Terminal-Bench 4.1's 66 tasks — Vetto's post (23 November) says the judge that built the set flagged 60 findings across 23 of 66 Terminal-Bench 4.1 tasks (about 35%). On its own tasks the best configuration (GPT-6.2 Astra with Codex CLI) resolves 66.7%, only three configurations pass more than half their trials, one task is unsolved, and of 980 failed trials the authors attribute about 52% to overfitting, 31% to misjudgement and 9% to mishandling. Catch: the auditor is the benchmark's author and a company with a pipeline to sell; the categories are its own. Built by: Vetto Research (Victor Elias, Lucas Smaira) · Artefacts: tasks on GitHub, Harbor Hub and Hugging Face, leaderboard; licence not stated · Signal: 2 HN points. Source: https://vetto.ai/companies/terminal-tasks-v2/

- Novyn looped decider 0.9: an open-weight model that picks one of up to 255 options without generating text — A frozen Thinking Machines research base (24 layers, the middle 12 looped ten times per request) with a single trained 255 x 2,304 decision head. On public text cases of JevBench it gets 210 of 231 (90.91%) against 90.48% for Jev 1.14 and 90.04% for Perplexity Decider 1.3; median decision 62.8 ms on four H200s. Catch: comparisons are not like-for-like (finite-choice prompts versus native question types), warm serial speed test, training write-up promised but not yet published, and the company uses it internally to categorise employee work. Built by: Novyn Labs · Artefacts: weights on Hugging Face (novyn/novyn-looped-decider-v0_9), post · Signal: 2 HN points. Source: https://www.novyn.ai/blog/announcing-novyn-looped-decision-0.9/
